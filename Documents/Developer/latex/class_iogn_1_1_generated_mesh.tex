{\footnotesize\ttfamily \label{class_iogn_1_1_generated_mesh_afb85c3f28b89a17725a0fae633f1e5a3} 
Iogn::\+\+Generated\+Mesh::\+\+Generated\+Mesh (\begin{DoxyParamCaption}\item[{const std::\+string \&}]{parameters}{, }\item[{int}]{proc\+\_\+count}{ = {\ttfamily 1}, }\item[{int}]{my\+\_\+proc}{ = {\ttfamily 0}}\end{DoxyParamCaption})\hspace{0.3cm}{\ttfamily [explicit]}}

Generate a cube mesh of size {\ttfamily num\+\_\+x} by {\ttfamily num\+\_\+y} by {\ttfamily num\+\_\+z} elements. By default, the mesh is generated on a single processor. If {\ttfamily proc\+\_\+count} is greater than 1, then the mesh will be distributed over {\ttfamily proc\+\_\+count} processors and this process will get the portion of the mesh for {\ttfamily my\+\_\+proc}. \doxylink{requirements_The}{The} mesh will be decomposed along the {\ttfamily Z} axis so {\ttfamily num\+\_\+z} must be greater than or equal to {\ttfamily proc\+\_\+count} and for even distribution of the hexes {\ttfamily num\+\_\+z} mod {\ttfamily proc\+\_\+count} should be zero.

\doxylink{requirements_The}{The} mesh can optionally include shell elements along each face of the cube mesh. These are specified via the {\ttfamily add\+\_\+shell\+\_\+block} function.

\doxylink{requirements_The}{The} mesh can optionally include nodesets/\+sidesets along each face of the cube mesh. These are specified via the {\ttfamily add\+\_\+nodesets} and {\ttfamily add\+\_\+sidesets} functions.

If the {\ttfamily parameters} string constructor is used, the string is parsed to determine the intervals in each direction and, optionally, additional information. \doxylink{requirements_The}{The} form of the string is "{}\+Ix\+Jx\+K"{} where I, J, and K are the number of intervals in the X, Y, and Z directions respectively and the "{}x"{} are literal {\ttfamily x} characters. For example, the constructor \doxylink{class_iogn_1_1_generated_mesh}{Generated\+Mesh}("{}10x12x14"{}) will create the same mesh as Generated\+Mesh(10,12,14)

Additional valid options are:\+

\item {\ttfamily show} -- no argument, prints out a summary of the Generated\+Mesh() parameters. \doxylink{requirements_The}{The} output will look similar to:\+

\item {\ttfamily tets} -- no argument -\/ specifies that each hex should be split into 6 tetrahedral elements. Cannot currently be used with shells or sidesets.
\item {\ttfamily pyramids} -- no argument -\/ specifies that each hex should be split into 6 pyramidal elements.
\item {\ttfamily shell} -- argument = x\+Xy\+YzZ which specifies whether there is a shell block at that location. {\ttfamily x} is minimum x face, {\ttfamily X} is maximum x face, similarly for y and z. Note that the argument string is a single multicharacter string. You can add multiple shell blocks to a face, for example, shell:\+xxx would add three layered shell blocks on the minimum x face. An error is output if a non x\+Xy\+YzZ character is found, but execution continues.
\item {\ttfamily nodeset} -- argument = x\+Xy\+YzZ which specifies whether there is a nodeset at that location. {\ttfamily x} is minimum x face, {\ttfamily X} is maximum x face, similarly for y and z. Note that the argument string is a single multicharacter string. You can add multiple nodesets to a face, for example, nodeset:\+xxx would add three nodesets on the minimum x face. An error is output if a non x\+Xy\+YzZ character is found, but execution continues.
\item {\ttfamily sideset} -- argument = x\+Xy\+YzZ which specifies whether there is a sideset at that location. {\ttfamily x} is minimum x face, {\ttfamily X} is maximum x face, similarly for y and z. Note that the argument string is a single multicharacter string. You can add multiple sidesets to a face, for example, sideset:\+xxx would add three sidesets on the minimum x face. An error is output if a non x\+Xy\+YzZ character is found, but execution continues. If there is a shell block specified on that face, then the sideset will be on the shell elements; else the sideset will be on the hex elements.
\item {\ttfamily zdecomp} -- argument = n0, n1, n2, ..., n\+\#proc-\/1 which are the number of intervals in the z direction for each processor in a pallel run. If this option is specified, then the total number of intervals in the z direction is the sum of the n0, n1, ... An interval count must be specified for each processor. If this option is not specified, then the number of intervals on each processor in the z direction is num\+Z/\+num\+Proc with the extras added to the lower numbered processors.
\item {\ttfamily scale} -- argument = xs, ys, zs which are the scale factors in the x, y, and z directions. All three must be specified if this option is present.
\item {\ttfamily offset} -- argument = xoff, yoff, zoff which are the offsets in the x, y, and z directions. All three must be specified if this option is present.
\item {\ttfamily bbox} -- argument = xmin, ymin, zmin, xmax, ymax, zmax which specify the lower left and upper right corners of the bounding box for the generated mesh. This will calculate the scale and offset which will fit the mesh in the specified box. All calculations are based on the currently active interval settings. If scale or offset or zdecomp specified later in the option list, you may not get the desired bounding box.
\item {\ttfamily rotate} -- argument = axis,angle,axis,angle,... where axis is {\ttfamily x}, {\ttfamily y}, or {\ttfamily z} and angle is the rotation angle in degrees. Multiple rotations are cumulative. \doxylink{requirements_The}{The} composite rotation matrix is applied at the time the coordinates are retrieved after scaling and offset are applied.
