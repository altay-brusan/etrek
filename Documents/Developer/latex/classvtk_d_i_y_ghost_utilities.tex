\doxysubsection{Detailed Description}
Utilities to produce ghost cells between a collection of data sets of same type. 

\doxylink{classvtk_d_i_y_ghost_utilities}{vtk\+DIYGhost\+Utilities} is a set of utilities which produce ghost cells between a collection of data sets of same type, using DIY.

Ghosts are computed from scratch, even if parts of the input already own ghosts. In such instance, ghosts are treated as if they didn\textquotesingle{}t exist in the input.

Mixed types in the input {\ttfamily \doxylink{classvtk_composite_data_set}{vtk\+Composite\+Data\+Set}} are supported, in the sense that ghost cells are only exchanged between blocks of same type. Similarly, ghosts are exchanged between blocks that connect.

Blocks connect with different criteria depending on their types:\+


\begin{DoxyItemize}
\item {\ttfamily \doxylink{classvtk_image_data}{vtk\+Image\+Data}}:\+ Blocks connect if they share face /\+ edge /\+ corner, if they share same dimension (1D /\+ 2D /\+ 3D), and if they have same orientation matrix and same spacing.
\item {\ttfamily \doxylink{classvtk_rectilinear_grid}{vtk\+Rectilinear\+Grid}}:\+ Blocks connect if the x, y, and z coordinate arrays match at their interfaces.
\item {\ttfamily \doxylink{classvtk_structured_grid}{vtk\+Structured\+Grid}}:\+ Blocks connect if external faces of the grids are mangled together, regardless of relative inner orientation. In other words, if grid 1 is spanned by (i1, j1, k1) indexing, and grid 2 is spanned by (i2, j2, k2) indexing, if on one face, (j1, k1) connects with (-\/i2, -\/j2), those 2 grids are connected and will exchange ghosts. Two grids partially fitting are discarded. In order for 2 grids to fit, one corner from one face of one grid needs to be an existing point in one face of the second grid. Additionally, every points from this corner on both grids need to match until the opposite corner (opposite w.\+r.\+t. each dimension) is reached, and this opposite corner of the grid junction needs to be a corner of either grid.
\item {\ttfamily \doxylink{classvtk_unstructured_grid}{vtk\+Unstructured\+Grid}}:\+ Blocks connect if the external surface of neighboring grids match. To do so, only points are looked at. If at least one point matches a point in a neighboring grid, then they are connected. If there are no point global ids in the input, the 3D position of the points is used to determine if grids match, up to floating point precision in the coordinates. Note that integer coordinates can be used with this pipeline. If global ids are present in the input point data, then the pipeline will only look at matching global ids, and ignore point positions.
\item {\ttfamily \doxylink{classvtk_poly_data}{vtk\+Poly\+Data}}:\+ Blocks connect if the boundary edges of neighboring poly data match. \doxylink{requirements_The}{The} filter behaves the same way it does with {\ttfamily \doxylink{classvtk_unstructured_grid}{vtk\+Unstructured\+Grid}}. Point positions are used to match points if point global ids are not present, and point global ids are used instead if they are present.
\end{DoxyItemize}

Points at the interface between 2 partitions are edited depending on the ownership of the point after the ghost points are generated. One can keep track of which process owns a non-\/ghost copy of the point if an array associating each point with its process id is available in the input.

\begin{DoxyNote}{Note}
Currently, only {\ttfamily \doxylink{classvtk_image_data}{vtk\+Image\+Data}}, {\ttfamily \doxylink{classvtk_rectilinear_grid}{vtk\+Rectilinear\+Grid}}, {\ttfamily \doxylink{classvtk_structured_grid}{vtk\+Structured\+Grid}}, {\ttfamily \doxylink{classvtk_unstructured_grid}{vtk\+Unstructured\+Grid}} and {\ttfamily \doxylink{classvtk_poly_data}{vtk\+Poly\+Data}} are implemented. Unless there is determining structural data added to subclasses of those classes, this filter should work well on subclasses of supported types.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
This warning only applies for {\ttfamily \doxylink{classvtk_unstructured_grid}{vtk\+Unstructured\+Grid}} and {\ttfamily \doxylink{classvtk_poly_data}{vtk\+Poly\+Data}} inputs. If there are duplicate points in the outer shell of an input partition, then this filter cannot decide on how to connect the cells properly when generating ghosts. \doxylink{requirements_The}{The} same phenomenon occurs when the outer shell of the partition has 2 points with the same global id. In such circumstances, use the {\ttfamily \doxylink{classvtk_static_clean_unstructured_grid}{vtk\+Static\+Clean\+Unstructured\+Grid}} or {\ttfamily \doxylink{classvtk_static_clean_poly_data}{vtk\+Static\+Clean\+Poly\+Data}} filter first in order to have a clean input. 
\end{DoxyWarning}
