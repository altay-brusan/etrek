\doxysubsection{Detailed Description}
Class defines API to manage the picking process.

\doxylink{requirements_The}{The} Picking \doxylink{class_manager}{Manager} (PM) coordinates picking across widgets simultaneously. It maintains a collection of registered pickers; when the manager is picked (e.\+g. \doxylink{classvtk_picking_manager_a6e809b7486d31404b4fec651d845ddb2}{vtk\+Picking\+Manager::\+\+Pick()}), a pick is run on each picker but only the best picker (e.\+g. closest to camera point) is selected. It finally returns the widget/\+representation or picker that was selected. \begin{DoxyWarning}{Warning}
Every time a vtk\+Widget and/\+or a \doxylink{classvtk_widget_representation}{vtk\+Widget\+Representation} is instantiated, it automatically registers its picker(s) and start being managed by delegating all its pick calls to the picking manager. It is possible to customize with the management in two ways:\+
\begin{DoxyItemize}
\item at the widget level, the "{}\+Manages\+Picking"{} variable can be changed from the widget/\+representation class to tell whether to use the manager or not.
\item Directly disable the picking manager itself with the boolean variable 
\end{DoxyItemize}
\end{DoxyWarning}
\begin{DoxySeeAlso}{See also}
Enabled using vtk\+Picking\+Manager::\+\+Enabled\+On(), Enabled\+Off(), Set\+Enabled(bool). 
\end{DoxySeeAlso}
\begin{DoxyParagraph}{Important:\+}
\doxylink{requirements_The}{The} picking manager is not active by default as it slightly reduces the performances when interacting with the scene. 
\end{DoxyParagraph}
\begin{DoxyParagraph}{Important:\+}
When registering pickers, a null object is considered valid because we can managed picker without any associated object. It is really important to note that a null object is different from one to an other !! This has been done to allow adding multiple times the same picker to the manager by not passing the referenced object to not force the suppression of all pickers 
\end{DoxyParagraph}
