\doxysubsection{Detailed Description}
\doxylink{requirements_The}{The} libtheora pre-\/1.\+0 legacy C API.\hypertarget{theora_8h_intro}{}\doxysubsection{\texorpdfstring{Introduction}{Introduction}}\label{theora_8h_intro}
This is the documentation for the libtheora legacy C API, declared in the \doxylink{theora_8h}{theora.\+h} header, which describes the old interface used before the 1.\+0 release. This API was widely deployed for several years and remains supported, but for new code we recommend the cleaner API declared in \doxylink{theoradec_8h}{theoradec.\+h} and \doxylink{theoraenc_8h}{theoraenc.\+h}.

libtheora is the reference implementation for \href{http://www.theora.org/}{\texttt{Theora}}, a free video codec. Theora is derived from On2\textquotesingle{}s VP3 codec with improved integration with Ogg multimedia formats by \href{http://www.xiph.org/}{\texttt{Xiph.\+Org}}.\hypertarget{theora_8h_overview}{}\doxysubsection{\texorpdfstring{Overview}{Overview}}\label{theora_8h_overview}
This library will both decode and encode theora packets to/\+from raw YUV frames. In either case, the packets will most likely either come from or need to be embedded in an Ogg stream. Use \href{http://xiph.org/ogg/}{\texttt{libogg}} or \href{http://www.annodex.net/software/liboggz/index.html}{\texttt{liboggz}} to extract/\+package these packets.\hypertarget{theora_8h_decoding}{}\doxysubsection{\texorpdfstring{Decoding Process}{Decoding Process}}\label{theora_8h_decoding}
Decoding can be separated into the following steps:\+
\begin{DoxyEnumerate}
\item initialise \doxylink{structtheora__info}{theora\+\_\+info} and \doxylink{structtheora__comment}{theora\+\_\+comment} structures using \doxylink{theora_8h_aaf7745451f72e81680e6c744a2966323}{theora\+\_\+info\+\_\+init()} and \doxylink{theora_8h_a4a347ef8413f11a5ab995e5f4e1fa407}{theora\+\_\+comment\+\_\+init()}:\+ \begin{DoxyVerb}theora_info     info;
theora_comment  comment;
  
theora_info_init(&info);
theora_comment_init(&comment);
\end{DoxyVerb}

\item retrieve header packets from Ogg stream (there should be 3) and decode into \doxylink{structtheora__info}{theora\+\_\+info} and \doxylink{structtheora__comment}{theora\+\_\+comment} structures using \doxylink{theora_8h_a4920b3e8d89dc6094f2c1e6478b37045}{theora\+\_\+decode\+\_\+header()}. See \doxysectlink{theora_8h_identification}{Identifying Theora Packets}{2} for more information on identifying which packets are theora packets. \begin{DoxyVerb}int i;
for (i = 0; i < 3; i++)
{
  (get a theora packet "op" from the Ogg stream)
  theora_decode_header(&info, &comment, op);
}
\end{DoxyVerb}

\item initialise the decoder based on the information retrieved into the \doxylink{structtheora__info}{theora\+\_\+info} struct by \doxylink{theora_8h_a4920b3e8d89dc6094f2c1e6478b37045}{theora\+\_\+decode\+\_\+header()}. You will need a \doxylink{structtheora__state}{theora\+\_\+state} struct. \begin{DoxyVerb}theora_state state;

theora_decode_init(&state, &info);
\end{DoxyVerb}

\item pass in packets and retrieve decoded frames! See the \doxylink{structyuv__buffer}{yuv\+\_\+buffer} documentation for information on how to retrieve raw YUV data. \begin{DoxyVerb}yuf_buffer buffer;
while (last packet was not e_o_s) {
  (get a theora packet "op" from the Ogg stream)
  theora_decode_packetin(&state, op);
  theora_decode_YUVout(&state, &buffer);
}
\end{DoxyVerb}

\end{DoxyEnumerate}\hypertarget{theora_8h_identification}{}\doxysubsubsection{\texorpdfstring{Identifying Theora Packets}{Identifying Theora Packets}}\label{theora_8h_identification}
All streams inside an Ogg file have a unique serial\+\_\+no attached to the stream. Typically, you will want to
\begin{DoxyItemize}
\item retrieve the serial\+\_\+no for each b\+\_\+o\+\_\+s (beginning of stream) page encountered within the Ogg file;
\item test the first (only) packet on that page to determine if it is a theora packet;
\item once you have found a theora b\+\_\+o\+\_\+s page then use the retrieved serial\+\_\+no to identify future packets belonging to the same theora stream.
\end{DoxyItemize}

Note that you {\itshape cannot} use \doxylink{theora_8h_ae4d17b60e0870a4dbf2b0c003af2a1a0}{theora\+\_\+packet\+\_\+isheader()} to determine if a packet is a theora packet or not, as this function does not perform any checking beyond whether a header bit is present. Instead, use the \doxylink{theora_8h_a4920b3e8d89dc6094f2c1e6478b37045}{theora\+\_\+decode\+\_\+header()} function and check the return value; or examine the header bytes at the beginning of the Ogg page.

Meta data is stored as a series of (tag, value) pairs, in length-\/encoded string vectors. \doxylink{requirements_The}{The} first occurence of the \textquotesingle{}=\textquotesingle{} character delimits the tag and value. Report the granulepos shift radix

When embedded in Ogg, Theora uses a two-\/part granulepos, splitting the 64-\/bit field into two pieces. \doxylink{requirements_The}{The} more-\/significant section represents the frame count at the last keyframe, and the less-\/significant section represents the count of frames since the last keyframe. In this way the overall field is still non-\/decreasing with time, but usefully encodes a pointer to the last keyframe, which is necessary for correctly restarting decode after a seek.

This function reports the number of bits used to represent the distance to the last keyframe, and thus how the granulepos field must be shifted or masked to obtain the two parts.

Since libtheora returns compressed data in an \doxylink{structogg__packet}{ogg\+\_\+packet} structure, this may be generally useful even if the Theora packets are not being used in an Ogg container.
