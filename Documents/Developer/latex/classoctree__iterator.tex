\subsubsection*{template$<$typename T\+\_\+, typename R\+\_\+, typename P\+\_\+, typename O\+\_\+, typename OP\+\_\+, int d\+\_\+ = 3$>$\newline
class octree\+\_\+iterator$<$ T\+\_\+, R\+\_\+, P\+\_\+, O\+\_\+, OP\+\_\+, d\+\_\+ $>$}
An octree iterator. 

Unlike most STL container iterators, octree iterators contain some state that most developers will be interested in. Specifically, the iterator may be set to traverse siblings but not children, only leaf nodes, or all nodes in an octree. Also, the bounding box of an octree node is implicit in its position in the hierarchy; since octree nodes themselves do not contain their position relative to their parents it is up to the iterator to provide bounding box information.
