\doxysubsection{Detailed Description}
Extracts outer surface (as \doxylink{classvtk_poly_data}{vtk\+Poly\+Data}) of any dataset. 

\doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} is a general-\/purpose filter to extract boundary geometry (and associated data) from any type of dataset. Geometry is obtained as follows:\+ all 0D, 1D, and 2D cells are extracted. All 2D faces that are used by only one 3D cell (i.\+e., boundary faces) are extracted. \doxylink{requirements_The}{The} filter will handle any type of dataset, including unstructured grids with non-\/linear cells. (See also \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} for additional documentation and information -\/ \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} is the preferred filter to use in most cases and may be deprecated in the future.)

\doxylink{requirements_The}{The} filter only has only a few options:\+ methods for passing through point and cell ids (to support picking); and controls for nonlinear cell subdivision. At this time \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} has the distinction of being able to process non-\/linear cells requiring subdivision. For this reason, \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} should be used with non-\/linear cells; otherwise \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} should be used. (Note:\+ by default this filter will delegate processing of linear vtk\+Unstructured\+Grids to \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} as \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} is so much faster. And \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} will delegate to \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} when it encounters nonlinear cells.)\hypertarget{classvtk_data_set_surface_filter_FastMode}{}\doxysubsection{\texorpdfstring{Fast Mode}{Fast Mode}}\label{classvtk_data_set_surface_filter_FastMode}
\doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} is sometimes used to simply render a 3D dataset. In which case we only are concerned about an approximate representation of the data and not necessarily the true exterior surface. In that case, simply set the Fast\+Mode flag to true.

Currently Fast\+Mode is used when extracting surface from a structured dataset or when {\ttfamily Delegation} is true. When Delegation is true, the flag is passed on to {\ttfamily \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter}} (see {\ttfamily \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter}:\+Set\+Fast\+Mode}).

\begin{DoxyWarning}{Warning}
At one time, \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} was a faster version of \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} when processing unstructured grids, however \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} is now faster. Also, \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} typically uses more memory than \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter}. Consequently as a convenience to the user, \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} will delegate to \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} when processing linear vtk\+Unstructured\+Grids. This typically produces a 5-\/10x speed up. (See \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} for more information.) This delegation can be disabled by setting the Delegation data member.

\doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} will generally not preserve topological connectivity. In other words, the output polygonal primitives may not be connected although in the originating dataset the boundary entities (e.\+g., faces) may have been connected. This can result in issues for filters that expect proper topological connectivity (e.\+g., \doxylink{classvtk_quadric_decimation}{vtk\+Quadric\+Decimation} or \doxylink{classvtk_feature_edges}{vtk\+Feature\+Edges}).

A key step in this algorithm (for 3D cells) is to count the number times a face is used by a cell. If used only once, then the face is considered a boundary face and sent to the filter output. \doxylink{requirements_The}{The} filter determines this by creating a hash table of faces:\+ faces that are placed into the hash table a single time are used only once, and therefore sent to the output. Thus large amounts of extra memory is necessary to build the hash table. This obsoleted approach requires a significant amount of memory, and is a significant bottleneck to threading.

This filter may create duplicate points. Unlike \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter}, it does not have the option to merge points. However it will eliminate points not used by any output polygonal primitive (i.\+e., not on the boundary).
\end{DoxyWarning}
