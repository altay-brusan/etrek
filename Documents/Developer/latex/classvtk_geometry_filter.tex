\doxysubsection{Detailed Description}
extract boundary geometry from dataset (or convert data to polygonal type) 

\doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} is a general-\/purpose filter to extract dataset boundary geometry, topology, and associated attribute data from any type of dataset. Geometry is obtained as follows:\+ all 0D, 1D, and 2D cells are extracted. All 2D faces that are used by only one 3D cell (i.\+e., boundary faces) are extracted. It also is possible to specify conditions on point ids, cell ids, and on a bounding box (referred to as "{}\+Extent"{}) to control the extraction process. This point and cell id-\/ and extent-\/based clipping is a powerful way to "{}see inside"{} datasets; however it may impact performance significantly.

This filter may also be used to convert any type of data to polygonal type. This is particularly useful for surface rendering. \doxylink{requirements_The}{The} conversion process may be less than satisfactory for some 3D datasets. For example, this filter will extract the outer surface of a volume or structured grid dataset (if point, cell, and extent clipping is disabled). (For structured data you may want to use \doxylink{classvtk_image_data_geometry_filter}{vtk\+Image\+Data\+Geometry\+Filter}, \doxylink{classvtk_structured_grid_geometry_filter}{vtk\+Structured\+Grid\+Geometry\+Filter}, \doxylink{classvtk_extract_unstructured_grid}{vtk\+Extract\+Unstructured\+Grid}, \doxylink{classvtk_rectilinear_grid_geometry_filter}{vtk\+Rectilinear\+Grid\+Geometry\+Filter}, or \doxylink{classvtk_extract_v_o_i}{vtk\+Extract\+VOI}.)

Another important feature of \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} is that it preserves topological connectivity. This enables filters that depend on correct connectivity (e.\+g., \doxylink{classvtk_quadric_decimation}{vtk\+Quadric\+Decimation}, \doxylink{classvtk_feature_edges}{vtk\+Feature\+Edges}, etc.) to operate properly . It is possible to label the output polydata with an originating cell (Pass\+Through\+Cell\+Ids) or point id (Pass\+Through\+Point\+Ids). \doxylink{requirements_The}{The} output precision of created points (if they need to be created) can also be specified.

Finally, this filter takes an optional second, \doxylink{classvtk_poly_data}{vtk\+Poly\+Data} input. This input represents a list of faces that are to be excluded from the output of \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter}.

\begin{DoxyWarning}{Warning}
While \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} and \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} perform similar operations, there are important differences as follows:\+
\begin{DoxyEnumerate}
\item \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} can preserve (using Remove\+Ghost\+Interfaces) topological connectivity. \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} produces output primitives which may be disconnected from one another.
\item \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} can generate output based on cell ids, point ids, and/\+or extent (bounding box) clipping. \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} strictly extracts the boundary surface of a dataset.
\item \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} is much faster than \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter}, because it\textquotesingle{}s multi-\/threaded. As a result, \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} will delegate the processing of linear unstructured grids to \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter}.
\item \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} can (currently) only handle linear cells. \doxylink{requirements_The}{The} filter will delegate to \doxylink{classvtk_data_set_surface_filter}{vtk\+Data\+Set\+Surface\+Filter} for higher-\/order cells. (This is a historical artifact and may be rectified in the future.)
\end{DoxyEnumerate}

If point merging (Merging\+Off) is disabled, the filter will (if possible) use the input points and point attributes. This can result in a lot of unused points in the output, at some gain in filter performance. If enabled, point merging will generate only new points that are used by the output polydata cells.

This class is templated. It may run slower than serial execution if the code is not optimized during compilation. Build in Release or Release\+With\+Debug\+Info.

This class has been threaded with \doxylink{classvtk_s_m_p_tools}{vtk\+SMPTools}. Using TBB or other non-\/sequential type (set in the CMake variable VTK\+\_\+\+SMP\+\_\+\+IMPLEMENTATION\+\_\+\+TYPE) may improve performance significantly.
\end{DoxyWarning}
