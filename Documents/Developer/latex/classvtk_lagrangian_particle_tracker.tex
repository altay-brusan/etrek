\doxysubsection{Detailed Description}
Filter to inject and track particles in a flow. 

Introduce Lagrangian\+Particle\+Tracker

This is a very flexible and adaptive filter to inject and track particles in a flow. It takes three inputs :\+
\begin{DoxyItemize}
\item port 0 :\+ Flow Input, a volumic dataset containing data to integrate with, any kind of data object, support distributed input.
\item port 1 :\+ Seed (source) Input, a dataset containing point to generate particles with, any kind of data object, support distributed input. Only first leaf of composite dataset is used.
\item port 2 :\+ Optional Surface Input, containing dataset to interact with, any kind of data object, support distributed input.
\end{DoxyItemize}

It has two outputs :\+
\begin{DoxyItemize}
\item port 0 :\+ Particle\+Paths :\+ a multipiece of poly\+Data (one per thread) of poly\+Lines showing the paths of particles in the flow
\item port 1 :\+ Particle\+Interactions :\+ empty if no surface input, contains a a multiblock with as many children as the number of threads, each children containing a multiblock with the same structure as the surfaces. \doxylink{requirements_The}{The} leafs of these structures contain a polydata of vertices corresponding to the interactions. with the same composite layout of surface input if any, showing all interactions between particles and the surface input.
\end{DoxyItemize}

It has a parallel implementation which streams particle between domains.

\doxylink{requirements_The}{The} most important parameters of this filter is it\textquotesingle{}s integration\+Model. Only one integration model implementation exist currently in Para\+View ,\doxylink{classvtk_lagrangian_matida_integration_model}{vtk\+Lagrangian\+Matida\+Integration\+Model} but the design enables plugin developers to expand this tracker by creating new models. A model can define :\+
\begin{DoxyItemize}
\item \doxylink{requirements_The}{The} number of integration variable and new user defined integration variable
\item the way the particle are integrated
\item the way particles intersect and interact with the surface
\item the way free\+Flight termination is handled
\item Pre\+Process and Post\+Process methods
\item Manual Integration, Manual partichle shifting see \doxylink{classvtk_lagrangian_basic_integration_model}{vtk\+Lagrangian\+Basic\+Integration\+Model} and \doxylink{classvtk_lagrangian_matida_integration_model}{vtk\+Lagrangian\+Matida\+Integration\+Model} for more information
\end{DoxyItemize}

It also let the user choose the Locator to use when integrating in the flow, as well as the Integrator to use. Integration steps are also highly configurable, step, step min and step max are passed down to the integrator (hence min and max does not matter with a non adaptive integrator like RK4/\+5)

An Integration\+Model is a very specific \doxylink{classvtk_function_set}{vtk\+Function\+Set} with a lot of features allowing inherited classes to concentrate on the mathematical part of the code. a Particle is basically a class wrapper around three table containing variables about the particle at previous, current and next position. \doxylink{requirements_The}{The} particle is passed to the integrator, which use the integration model to integrate the particle in the flow.

It has other features also, including :\+
\begin{DoxyItemize}
\item Adaptative Step Reintegration, to retry the step with different time step when the next position is too far
\item Different kind of cell length computation, including a divergence theorem based computation
\item Optional lines rendering controlled by a threshold
\item Ghost cell support
\item Non planar quad interaction support
\item Built-\/in support for surface interaction including, terminate, bounce, break-\/up and pass-\/through surface \doxylink{requirements_The}{The} serial and parallel filters are fully tested.
\end{DoxyItemize}
