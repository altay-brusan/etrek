\doxysubsection{Detailed Description}
Abstract superclass for all arrays. 

\doxylink{classvtk_abstract_array}{vtk\+Abstract\+Array} is an abstract superclass for data array objects. This class defines an API that all subclasses must support. \doxylink{requirements_The}{The} data type must be assignable and copy-\/constructible, but no other assumptions about its type are made. Most of the subclasses of this array deal with numeric data either as scalars or tuples of scalars. A program can use the \doxylink{classvtk_abstract_array_a06a2da470f2a716eb7b92cd631c25875}{Is\+Numeric()} method to check whether an instance of \doxylink{classvtk_abstract_array}{vtk\+Abstract\+Array} contains numbers. It is also possible to test for this by attempting to Safe\+Down\+Cast an array to an instance of \doxylink{classvtk_data_array}{vtk\+Data\+Array}, although this assumes that all numeric arrays will always be descended from \doxylink{classvtk_data_array}{vtk\+Data\+Array}.

Every array has a character-\/string name. \doxylink{requirements_The}{The} naming of the array occurs automatically when it is instantiated, but you are free to change this name using the Set\+Name() method. (\doxylink{requirements_The}{The} array name is used for data manipulation.)

This class (and subclasses) use two forms of addressing elements:\+
\begin{DoxyItemize}
\item Value Indexing:\+ \doxylink{requirements_The}{The} index of an element assuming an array-\/of-\/structs memory layout.
\item Tuple/\+\+Component Indexing:\+ Explicitly specify the tuple and component indices.
\end{DoxyItemize}

It is also worth pointing out that the behavior of the "{}\+Insert\texorpdfstring{$\ast$}{*}"{} methods of classes in this hierarchy may not behave as expected. They work exactly as the corresponding "{}\+Set\texorpdfstring{$\ast$}{*}"{} methods, except that memory allocation will be performed if acting on a value past the end of the array. If the data already exists, "{}inserting"{} will overwrite existing values, rather than shift the array contents and insert the new data at the specified location.

If code is modifying contents of an existing array, it is required that one calls {\ttfamily \doxylink{classvtk_abstract_array_a965b737d222e879f10e053beb996a329}{vtk\+Abstract\+Array::\+\+Modified()}} explicitly after the modifications to the contents are completed. APIs like {\ttfamily \doxylink{classvtk_abstract_array_a5816fc39a2a6706d57b6e7e9832387bd}{Set\+Tuple}} etc. don\textquotesingle{}t call {\ttfamily \doxylink{classvtk_abstract_array_a965b737d222e879f10e053beb996a329}{Modified}} to avoid performance hits. Unless {\ttfamily \doxylink{classvtk_abstract_array_a965b737d222e879f10e053beb996a329}{Modified}} is called, various cached entities, like array range, map created for {\ttfamily \doxylink{classvtk_abstract_array_ad8dad1616c007558cca180a07dfe382b}{Lookup\+Value}} may become obsolete and yield incorrect results.

\begin{DoxyWarning}{Warning}
In VTK 9.\+4, new method {\ttfamily nlohmann::\+json vtk\+Abstract\+Array::\+\+Serialize\+Values()} was introduced which required exposing symbols from VTK::\+nlohmannjson library in public API. This method will be removed in VTK 9.\+5 as it caused difficulty for downstream projects that linked to a different nlohmannjson. It cannot be deprecated because doing so prevents fixing the underlying issue.
\end{DoxyWarning}

Populate the given \doxylink{classvtk_variant_array}{vtk\+Variant\+Array} with a set of distinct values taken on by the requested component (or, when passed -\/1, by the tuples as a whole). If the set of prominent values has more than 32 entries, then the array is assumed to be continuous in nature and no values are returned.

This method takes 2 parameters:\+ {\itshape uncertainty} and {\itshape minimum\+Prominence}. Note that this set of returned values may not be complete if {\itshape uncertainty} and {\itshape minimum\+Prominence} are both larger than 0.\+0; in order to perform interactively, a subsample of the array is used to determine the set of values.

\doxylink{requirements_The}{The} first parameter ({\itshape uncertainty}, U) is the maximum acceptable probability that a prominent value will not be detected. Setting this to 0 will cause every value in the array to be examined.

\doxylink{requirements_The}{The} second parameter ({\itshape minimum\+Prominence}, P) specifies the smallest relative frequency (in \+[0,1]\+) with which a value in the array may occur and still be considered prominent. Setting this to 0 will force every value in the array to be traversed. Using numbers close to 0 for this parameter quickly causes the number of samples required to obtain the given uncertainty to subsume the entire array, as rare occurrences require frequent sampling to detect.

For an array with T tuples and given uncertainty U and mininumum prominence P, we sample N values, with N = f(T; P, U). We want f to be sublinear in T in order to interactively handle large arrays; in practice, we can make f independent of T:\+ $ N >= \frac{5}{P}\mathrm{ln}\left(\frac{1}{PU}\right) $, but note that small values of P are costly to achieve. \doxylink{requirements_The}{The} default parameters will locate prominent values that occur at least 1 out of every 1000 samples with a confidence of 0.\+999999 (= 1 -\/ 1e6). Thanks to Seshadri Comandur (Sandia National Laboratories) for the bounds on the number of samples.
