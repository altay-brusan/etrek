\doxysubsection{Detailed Description}
logging framework for use in VTK and in applications based on VTK 

\doxylink{classvtk_logger}{vtk\+Logger} acts as the entry point to VTK\textquotesingle{}s logging framework. \doxylink{requirements_The}{The} implementation uses the loguru (\href{https://github.com/emilk/loguru}{\texttt{https:\+/\+/\+github.\+com/\+emilk/\+loguru}}). \doxylink{classvtk_logger}{vtk\+Logger} provides some static API to initialize and configure logging together with a collection of macros that can be used to add items to the generated log.

\doxylink{requirements_The}{The} logging framework is based on verbosity levels. Level 0-\/9 are supported in addition to named levels such as ERROR, WARNING, and INFO. When a log for a particular verbosity level is being generated, all log additions issued with verbosity level less than or equal to the requested verbosity level will get logged.

When using any of the logging macros, it must be noted that unless a log output is requesting that verbosity provided (or higher), the call is a no-\/op and the message stream or printf-\/style arguments will not be evaluated.\hypertarget{classvtk_logger_Setup}{}\doxysubsection{\texorpdfstring{Setup}{Setup}}\label{classvtk_logger_Setup}
To initialize logging, in your application\textquotesingle{}s {\ttfamily main()} you may call {\ttfamily vtk\+Logger::\+\+Init(argv, argc)}. This is totally optional but useful to time-\/stamp the start of the log. Furthermore, it can optionally detect verbosity level on the command line as {\ttfamily -\/v} (or any another string pass as the optional argument to {\ttfamily \doxylink{classvtk_logger_a9bb88d9631ffb75a42c40e01b8655ea7}{Init}}) that will be used as the verbosity level for logging on to {\ttfamily stderr}. By default, it is set to {\ttfamily 0} (or {\ttfamily INFO}) unless changed by calling {\ttfamily \doxylink{classvtk_logger_aafe642339f32388f839026a4087306c1}{vtk\+Logger::\+\+Set\+Stderr\+Verbosity}}.

In additional to logging to {\ttfamily stderr}, one can accumulate logs to one or more files using {\ttfamily \doxylink{classvtk_logger_afac662ba4d6c1a1d22f93715c8be6df5}{vtk\+Logger::\+\+Log\+To\+File}}. Each log file can be given its own verbosity level.

For multithreaded applications, you may want to name each of the threads so that the generated log can use human readable names for the threads. For that, use {\ttfamily \doxylink{classvtk_logger_a8af426d06d7ee55b601e5a8439993daf}{vtk\+Logger::\+\+Set\+Thread\+Name}}. Calling {\ttfamily \doxylink{classvtk_logger_a9bb88d9631ffb75a42c40e01b8655ea7}{vtk\+Logger::\+\+Init}} will set the name for the main thread.

You can choose to turn on signal handlers for intercepting signals. By default, all signal handlers are disabled. \doxylink{requirements_The}{The} following is a list of signal handlers and the corresponding static variable that can be used to enable/\+disable each signal handler.


\begin{DoxyItemize}
\item SIGABRT -\/ {\ttfamily vtk\+Logger::\+\+Enable\+Sigabrt\+Handler}
\item SIGBUS -\/ {\ttfamily vtk\+Logger::\+\+Enable\+Sigbus\+Handler}
\item SIGFPE -\/ {\ttfamily vtk\+Logger::\+\+Enable\+Sigfpe\+Handler}
\item SIGILL -\/ {\ttfamily vtk\+Logger::\+\+Enable\+Sigill\+Handler}
\item SIGINT -\/ {\ttfamily vtk\+Logger::\+\+Enable\+Sigint\+Handler}
\item SIGSEGV -\/ {\ttfamily vtk\+Logger::\+\+Enable\+Sigsegv\+Handler}
\item SIGTERM -\/ {\ttfamily vtk\+Logger::\+\+Enable\+Sigterm\+Handler}
\end{DoxyItemize}

To enable any of these signal handlers, set their value to {\ttfamily true} prior to calling {\ttfamily vtk\+Logger::\+\+Init(argc, argv)} or {\ttfamily \doxylink{classvtk_logger_a9bb88d9631ffb75a42c40e01b8655ea7}{vtk\+Logger::\+\+Init()}}.

When signal handlers are enabled, to prevent the logging framework from intercepting signals from your application, you can set the static variable {\ttfamily \doxylink{classvtk_logger_a008a4942dfd437dfb4590a4d5582a7ce}{vtk\+Logger::\+\+Enable\+Unsafe\+Signal\+Handler}} to {\ttfamily false} prior to calling {\ttfamily vtk\+Logger::\+\+Init(argc, argv)} or {\ttfamily \doxylink{classvtk_logger_a9bb88d9631ffb75a42c40e01b8655ea7}{vtk\+Logger::\+\+Init()}}.\hypertarget{classvtk_logger_Logging}{}\doxysubsection{\texorpdfstring{Logging}{Logging}}\label{classvtk_logger_Logging}
\doxylink{classvtk_logger}{vtk\+Logger} provides several macros (again, based on {\ttfamily loguru}) that can be used to add the log. Both printf-\/style and stream-\/style is supported. All printf-\/style macros are suffixed with {\ttfamily F} to distinguish them from the stream macros. Another pattern in naming macros is the presence of {\ttfamily V} e.\+g. {\ttfamily vtk\+VLog} vs {\ttfamily vtk\+Log}. A macro with the {\ttfamily V} prefix takes a fully qualified verbosity enum e.\+g. {\ttfamily vtk\+Logger::\+\+VERBOSITY\+\_\+\+INFO} or {\ttfamily vtk\+Logger::\+\+VERBOSITY\+\_\+0}, while the non-\/{\ttfamily V} variant takes the verbosity name e.\+g. {\ttfamily INFO} or {\ttfamily 0}.

\hypertarget{classvtk_logger_LoggingAndLegacyMacros}{}\doxysubsection{\texorpdfstring{Logging and VTK error macros}{Logging and VTK error macros}}\label{classvtk_logger_LoggingAndLegacyMacros}
VTK has long supported multiple macros to report errors, warnings and debug messages through {\ttfamily vtk\+Error\+Macro}, {\ttfamily vtk\+Warning\+Macro}, {\ttfamily vtk\+Debug\+Macro}, etc. In addition to performing the traditional message reporting via {\ttfamily \doxylink{classvtk_output_window}{vtk\+Output\+Window}}, these macros also log to the logging sub-\/system with appropriate verbosity levels.

To avoid the \doxylink{classvtk_logger}{vtk\+Logger} and \doxylink{classvtk_output_window}{vtk\+Output\+Window} both posting the message to the standard output streams, \doxylink{classvtk_output_window}{vtk\+Output\+Window} now supports an ability to specify terminal display mode, via {\ttfamily vtk\+Output\+Window::\+\+Set\+Display\+Mode}. If display mode is {\ttfamily vtk\+Output\+Window::\+\+DEFAULT} then the output window will not post messages originating from the standard error/\+warning/\+debug macros to the standard output if VTK is built with logging support. If VTK is not built with logging support, then \doxylink{classvtk_output_window}{vtk\+Output\+Window} will post the messages to the standard output streams, unless disabled explicitly.\hypertarget{classvtk_logger_Callbacks}{}\doxysubsection{\texorpdfstring{Custom callbacks/\+handlers for log messages}{Custom callbacks/\+handlers for log messages}}\label{classvtk_logger_Callbacks}
\doxylink{classvtk_logger}{vtk\+Logger} supports ability to register callbacks to call on each logged message. This is useful to show the messages in application specific viewports, e.\+g. a special message widget.

To register a callback use {\ttfamily \doxylink{classvtk_logger_a74f2657db81beb0578bd47963beac663}{vtk\+Logger::\+\+Add\+Callback}} and to remove a callback use {\ttfamily \doxylink{classvtk_logger_a2dc658bc8c7cfc3a7da249db19c242d9}{vtk\+Logger::\+\+Remove\+Callback}} with the id provided when registering the callback.
