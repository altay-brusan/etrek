\doxysubsection{Detailed Description}
Writer for IOSS (Sierra IO System). 

\doxylink{classvtk_i_o_s_s_writer}{vtk\+IOSSWriter} is a writer that uses the IOSS (Sierra IO System) library to write files. Currently this writer supports the Exodus file format. IOSS imposes certain restrictions on the aforementioned file format and hence it may not be possible to write every dataset as an Exodus file using this writer. This is rare for the Exodus.

This writer generates files using the same naming conventions that \doxylink{classvtk_i_o_s_s_reader}{vtk\+IOSSReader} understands.\hypertarget{classvtk_i_o_s_s_writer_SelectingBlocksSetsToWrite}{}\doxysubsection{\texorpdfstring{Selecting blocks and sets to write}{Selecting blocks and sets to write}}\label{classvtk_i_o_s_s_writer_SelectingBlocksSetsToWrite}
An IOSS file comprises of blocks and sets of various types. These are described by the enum {\ttfamily vtk\+IOSSReader::\+\+Entity\+Type}. If the input of the writer was initially read by the \doxylink{classvtk_i_o_s_s_reader}{vtk\+IOSSReader}, then the entity types can be automatically deduced. If it was not initially read by \doxylink{classvtk_i_o_s_s_reader}{vtk\+IOSSReader} (or even if it was), the assembly name and selectors can be utilized to define which blocks are e.\+g. element blocks, or side sets. {\ttfamily vtk\+IOSSWriter::\+\+Set\+Assembly\+Name(...)} can be used to set the assembly, and {\ttfamily vtk\+IOSSWriter::\+\+Add\+Selector(...)} (or one of its convenience variants) can be used to add selectors. If no selectors have been defined all partitions will be treated as element blocks.

Typical usage is as follows:\+

Similar arrays (or fields as IOSS refers to them) to read from each of the blocks or sets can be specified using the {\ttfamily \doxylink{classvtk_data_array_selection}{vtk\+Data\+Array\+Selection}} instance returned using {\ttfamily \doxylink{classvtk_i_o_s_s_writer_aea1fa9f041bdd33b16a6420e70730cf7}{vtk\+IOSSWriter::\+\+Get\+Field\+Selection}} (or one of its convenience variants).

An upstream request is defined by the contents of the request information object. \doxylink{requirements_The}{The} input to the request is stored in the output information vector passed to Process\+Request. \doxylink{requirements_The}{The} results of an upstream request are stored in the input information vector passed to Process\+Request.
