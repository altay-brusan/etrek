\doxysubsection{Detailed Description}
\doxylink{classvtk_data_array}{vtk\+Data\+Array} code generator/\+dispatcher. 

\doxylink{classvtk_array_dispatch}{vtk\+Array\+Dispatch} implements a mechanism for generating optimized code for multiple subclasses of \doxylink{classvtk_data_array}{vtk\+Data\+Array} at once. Using a Type\+List based approach (see \doxylink{classvtk_type_list}{vtk\+Type\+List}), a templated worker implementation is generated for a restricted or unrestricted set of \doxylink{classvtk_data_array}{vtk\+Data\+Array} subclasses.

A more detailed description of this class and related tools can be found \href{https://docs.vtk.org/en/latest/design_documents/array_dispatch.html}{\texttt{here}}.

\doxylink{requirements_The}{The} primary goals of this class are to simplify multi-\/array dispatch implementations, and provide tools to lower compilation time and binary size (i.\+e. avoiding \textquotesingle{}template explosions\textquotesingle{}).

\doxylink{classvtk_array_dispatch}{vtk\+Array\+Dispatch} is also intended to replace code that currently relies on the encapsulation-\/breaking vtk\+Data\+Array::\+\+Get\+Void\+Pointer method. Not all subclasses of \doxylink{classvtk_data_array}{vtk\+Data\+Array} use the memory layout assumed by Get\+Void\+Pointer; calling this method on, e.\+g. a \doxylink{classvtk_s_o_a_data_array_template}{vtk\+SOAData\+Array\+Template} will trigger a deep copy of the array data into an AOS buffer. This is very inefficient and should be avoided.

\doxylink{requirements_The}{The} \doxylink{vtk_data_array_range_8h}{vtk\+Data\+Array\+Range.\+h} utilities are worth mentioning here, as they allow \doxylink{classvtk_array_dispatch}{vtk\+Array\+Dispatch} workers to operate on selected concrete subclasses for \textquotesingle{}fast paths\textquotesingle{}, yet fallback to using the slower \doxylink{classvtk_data_array}{vtk\+Data\+Array} API for uncommon array types. This helps mitigate the "{}template explosion"{} issues that can result from instantiating a large worker functions for many array types.

These dispatchers extend the basic functionality of vtk\+Template\+Macro with the following features:\+
\begin{DoxyItemize}
\item Multiarray dispatch:\+ A single call can dispatch up to 3 arrays at once.
\item Array restriction:\+ \doxylink{requirements_The}{The} set of valid arrays for a particular dispatch can be restricted. For example, if only \doxylink{classvtk_double_array}{vtk\+Double\+Array} or \doxylink{classvtk_float_array}{vtk\+Float\+Array} will be passed into the call, the dispatcher will only generate code paths that use those arrays.
\item Value\+Type restriction:\+ If both SoA and AoS arrays need to be supported, but only certain Value\+Types are expected, the dispatcher can restrict itself to only use arrays that match this criteria.
\item Application-\/wide array restrictions:\+ If a VTK application uses only a few arraytype /\+ valuetype combinations, certain dispatchers will eliminate paths using unsupported arrays at compile time.
\end{DoxyItemize}

\doxylink{requirements_The}{The} basic Dispatch implementation will generate code paths for all arrays in the application-\/wide array list, and operates on a single array.

Dispatchers that start with Dispatch2 operate on 2 arrays simultaneously, while those that begin with Dispatch3 operate on 3 arrays.

To reduce compile time and binary size, the following dispatchers can be used to restrict the set of arrays that will be used. There are versions of these that operate on 1, 2, or 3 arrays:\+


\begin{DoxyItemize}
\item \doxylink{structvtk_array_dispatch_1_1_dispatch_by_array}{Dispatch\+By\+Array}:\+ Accepts an explicit Type\+List of arrays to consider. These dispatchers do NOT respect the application-\/wide array restrictions. Example usecase:\+ A filter that creates either \doxylink{classvtk_float_array}{vtk\+Float\+Array} or \doxylink{classvtk_double_array}{vtk\+Double\+Array} depending on configuration can use this to restrict itself to only these specific types. Note that these should not be used for operating on filter inputs, instead use \doxylink{structvtk_array_dispatch_1_1_dispatch_by_value_type}{Dispatch\+By\+Value\+Type}, which also considers variations in \doxylink{classvtk_data_array}{vtk\+Data\+Array} subclasses and respects the application-\/wide array restrictions.
\item \doxylink{structvtk_array_dispatch_1_1_dispatch_by_value_type}{Dispatch\+By\+Value\+Type}:\+ Accepts an explicit Type\+List of Value\+Types to consider. These dispatchers respect the application-\/wide array restrictions. Example usecase:\+ An image filter that operates on an input array that must have either a float or unsigned char Value\+Type.
\item Dispatch\+NBy\+Array\+With\+Same\+Value\+Type:\+ Multiarray dispatcher that accepts an explicit Type\+List of arrays for consideration. Generated code paths are further restricted to enforce that all dispatched arrays will have the same Value\+Type. Example usecase:\+ A filter that creates and operates on multiple arrays at the same time, where the arrays are guaranteed to have the same Value\+Type. Note that these should not be used for operating on filter inputs, instead use Dispatch\+NBy\+Same\+Value\+Type, which also considers variations in \doxylink{classvtk_data_array}{vtk\+Data\+Array} subclasses and respects the application-\/wide array restrictions.
\item Dispatch\+NBy\+Same\+Value\+Type:\+ Multiarray dispatcher that accepts an explicit Type\+List of Value\+Types to consider. Generated code paths are further restricted to enforce that all dispatched arrays will have the same Value\+Type. Example usecase:\+ A filter that creates a modified version of an input array using New\+Instance(). Both arrays may be passed into the dispatcher using a worker function that produces the output from the input.
\end{DoxyItemize}

Return value:\+ \doxylink{requirements_The}{The} Execute method of the dispatcher will return true if a code path matching the array arguments is found, or false if the arrays are not supported. If false is returned, the arrays will not be modified, and the worker will not be executed.

Workers:\+ \doxylink{requirements_The}{The} dispatch requires a Worker functor that performs the work. For single array, the functor must be callable where the first parameter is an array object. For 2-\/array dispatch, the first two arguments must be (array1, array2). For 3-\/array dispatch, the first three arguments must be (array1, array2, array3). Workers are passed by reference, so stateful functors are permitted if additional input/\+output data is needed and not being passed as additional parameters to the Execute method.
