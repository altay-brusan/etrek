\doxysubsection{Detailed Description}
\doxylink{classvtk_data_object_mesh_cache}{vtk\+Data\+Object\+Mesh\+Cache} is a class to store and reuse the mesh of a \doxylink{classvtk_data_set}{vtk\+Data\+Set}, while forwarding data arrays from another dataset. Composite structure of \doxylink{classvtk_data_set}{vtk\+Data\+Set} are also supported. This is specially useful when working with static meshes and transient data.\hypertarget{classvtk_data_object_mesh_cache_autotoc_md796}{}\doxysubsubsection{\texorpdfstring{Example of use case}{Example of use case}}\label{classvtk_data_object_mesh_cache_autotoc_md796}
Think about the \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter}. On first execution, it extracts boundaries of an input mesh alongside with the associated data. On the second execution, if the input mesh didn\textquotesingle{}t change and neither did the vtk\+Geometry\+Fitlers own properties, then there is no need for boundary extraction:\+ previous output mesh can be reused. Only the associated data should be forwarded.

Instead of implementing such logic itself, filter like the \doxylink{classvtk_geometry_filter}{vtk\+Geometry\+Filter} can instead rely on the \doxylink{classvtk_data_object_mesh_cache}{vtk\+Data\+Object\+Mesh\+Cache} in order to easily reuse the previously computed mesh, and forward the new data arrays.\hypertarget{classvtk_data_object_mesh_cache_autotoc_md797}{}\doxysubsubsection{\texorpdfstring{Details}{Details}}\label{classvtk_data_object_mesh_cache_autotoc_md797}
This helper relies on different elements:\+
\begin{DoxyItemize}
\item {\ttfamily Consumer}:\+ a \doxylink{classvtk_object}{vtk\+Object} using the helper. Any modifications on it invalidate cache.
\item {\ttfamily Original\+Data\+Object}:\+ the input \doxylink{classvtk_data_object}{vtk\+Data\+Object}. Should be either a \doxylink{classvtk_data_set}{vtk\+Data\+Set} or a composite of vtk\+Data\+Set.\+ \+The helper looks for its Mesh\+MTime.
\item {\ttfamily Cache}:\+ the output \doxylink{classvtk_data_object}{vtk\+Data\+Object} containing the mesh to reuse (or a composite)
\item {\ttfamily Original\+Ids}:\+ a list of original ids array name per attribute types, to forward from Original\+Data\+Object to Cache when asked to.
\end{DoxyItemize}

\doxylink{requirements_The}{The} {\ttfamily \doxylink{structvtk_data_object_mesh_cache_1_1_status}{Status}} structure reflects the state of those different elements. It is the user responsibility to check for the status before calling {\ttfamily \doxylink{classvtk_data_object_mesh_cache_a43c8f833bcacd96afbfa8253ae9527be}{Copy\+Cache\+To\+Data\+Object}}.

Attributes data are forwarded with {\ttfamily Copy\+Allocate} method. So output should be a subset of the input. Support for {\ttfamily Interpolate\+Allocate} is doable and may be added in the future.\hypertarget{classvtk_data_object_mesh_cache_autotoc_md798}{}\doxysubsubsection{\texorpdfstring{ \+Requirements}{ \+Requirements}}\label{classvtk_data_object_mesh_cache_autotoc_md798}
\doxylink{requirements_The}{The} data arrays forwarding rely on Global\+Ids arrays.

When using \doxylink{classvtk_composite_data_set}{vtk\+Composite\+Data\+Set}, every leaves should be of a supported data set type.
