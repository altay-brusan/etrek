\doxysubsection{Detailed Description}
simple threaded callback queue 

This callback queue executes pushed functions and functors on threads whose purpose is to execute those functions. By default, one thread is created by this class, so it is advised to set {\ttfamily Number\+Of\+Threads}. Upon destruction of an instance of this callback queue, remaining unexecuted threads are executed.

When a task is pushed, a {\ttfamily \doxylink{classvtk_threaded_callback_queue_1_1vtk_shared_future}{vtk\+Shared\+Future}} is returned. This instance can be used to get the returned value when the task is finished, and provides functionalities to synchronize the main thread with the status of its associated task.

All public methods of this class are thread safe.

Pushes a function f to be passed args... as arguments. f will be called as soon as a running thread has the occasion to do so, in a FIFO fashion. This method returns a {\ttfamily \doxylink{classvtk_threaded_callback_queue_1_1vtk_shared_future}{vtk\+Shared\+Future}}, which is an object allowing to synchronize the code.

All the arguments of {\ttfamily \doxylink{classvtk_threaded_callback_queue_a4cc5949e6c5c9adbed12b724ab6bdac3}{Push}} are stored persistently inside the queue. An argument passed as an lvalue reference will trigger a copy constructor call. It is thus advised, when possible, to pass rvalue references or smart pointers ({\ttfamily \doxylink{classvtk_smart_pointer}{vtk\+Smart\+Pointer}} or {\ttfamily std::\+shared\+\_\+ptr} for example)

\doxylink{requirements_The}{The} input function can be a pointer function, a lambda expression, a {\ttfamily std::\+function} a functor or a member function pointer.

If f is a functor, its copy constructor will be invoked if it is passed as an lvalue reference. Consequently, if the functor is somewhat heavy, it is advised to pass it as an rvalue reference or to wrap inside a smart pointer ({\ttfamily std::\+unique\+\_\+ptr} for example).

If f is a member function pointer, an instance of its host class needs to be provided in the second parameter. Similar to the functor case, it is advised in order to avoid calling the copy constructor to pass it as an rvalue reference or to wrap it inside a smart pointer.

void vtk\+Threaded\+Callback\+Queue::\+\+Wait (\begin{DoxyParamCaption}\item[{Shared\+Future\+ContainerT \&\&}]{prior\+Shared\+Future}{}\end{DoxyParamCaption})}

This method blocks the current thread until all the tasks associated with each shared future inside {\ttfamily prior\+Shared\+Future} has terminated.

It is in general more efficient to call this function than to call {\ttfamily \doxylink{classvtk_threaded_callback_queue_a72da7b2fbd9b4fd8931f81c4d93ddc4f}{Wait}} on each future individually because if any task associated with {\ttfamily prior\+Shared\+Future} is allowed to run (i.\+e. it is not depending on any other future) and is currently waiting in queue, this function will actually run it.

\doxylink{requirements_The}{The} current thread is blocked at most once by this function.

{\ttfamily Shared\+Future\+ContainerT} must have a forward iterator (presence of a {\ttfamily begin()} and {\ttfamily end()} member function).
