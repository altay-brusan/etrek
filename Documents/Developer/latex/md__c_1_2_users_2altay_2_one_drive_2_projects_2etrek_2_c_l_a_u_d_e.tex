{\bfseries{Key principle}}:\+ Lower-\/level modules (Core, View) do not depend on higher-\/level modules (Application). Common is an interface-\/only library providing shared types and contracts.\hypertarget{md__c_1_2_users_2altay_2_one_drive_2_projects_2etrek_2_c_l_a_u_d_e_autotoc_md9}{}\doxysubsection{\texorpdfstring{Common Module Pattern}{Common Module Pattern}}\label{md__c_1_2_users_2altay_2_one_drive_2_projects_2etrek_2_c_l_a_u_d_e_autotoc_md9}
Common is an INTERFACE library ({\ttfamily Common/\+\+Include/\+}) containing:\+
\begin{DoxyItemize}
\item Entity definitions shared across modules (User, Role, Worklist\+Entry, etc.)
\item Interface contracts (\doxylink{class_i_delegate}{IDelegate}, \doxylink{class_i_page_action}{IPage\+Action}, \doxylink{class_i_widget_delegate_builder}{IWidget\+Delegate\+Builder})
\item Repository interfaces (IWorklist\+Repository, IWorklist\+Field\+Configuration\+Repository)
\item Specification types (Launch\+Mode, Result, \doxylink{struct_date_time_span}{Date\+Time\+Span})
\end{DoxyItemize}

All modules include from Common via:\+ {\ttfamily \$\{COMMON\+\_\+\+INCLUDE\+\_\+\+DIR\}/\+\+[Module]\+/\+\+[Category]\+/\+\+[Header]\+.\doxylink{classvtk_en_sight_gold_combined_reader_1_1h}{h}}\hypertarget{md__c_1_2_users_2altay_2_one_drive_2_projects_2etrek_2_c_l_a_u_d_e_autotoc_md10}{}\doxysubsection{\texorpdfstring{Application Layer Pattern}{Application Layer Pattern}}\label{md__c_1_2_users_2altay_2_one_drive_2_projects_2etrek_2_c_l_a_u_d_e_autotoc_md10}
\doxylink{requirements_The}{The} Application module uses the {\bfseries{Strategy Pattern}} for different launch modes:\+
\begin{DoxyItemize}
\item {\ttfamily ILaunch\+Strategy} -\/ Base interface
\item {\ttfamily Main\+App\+Launch\+Strategy} -\/ Full application with authentication
\item {\ttfamily Demo\+Launch\+Strategy} -\/ Demo mode
\item {\ttfamily Developer\+Launch\+Strategy} -\/ Developer shortcuts
\item {\ttfamily Setting\+Manager\+Launch\+Strategy} -\/ Settings editor only
\item {\ttfamily User\+Manager\+Launch\+Strategy} -\/ User management only
\end{DoxyItemize}

Launch strategies are selected based on command-\/line arguments parsed by {\ttfamily Parse\+Launch\+Mode()}.\hypertarget{md__c_1_2_users_2altay_2_one_drive_2_projects_2etrek_2_c_l_a_u_d_e_autotoc_md11}{}\doxysubsection{\texorpdfstring{Delegate Pattern}{Delegate Pattern}}\label{md__c_1_2_users_2altay_2_one_drive_2_projects_2etrek_2_c_l_a_u_d_e_autotoc_md11}
\doxylink{requirements_The}{The} codebase extensively uses the {\bfseries{Builder + Delegate Pattern}} for UI components:\+
\begin{DoxyItemize}
\item {\bfseries{Builder}} classes construct UI components and wire dependencies
\item {\bfseries{Delegate}} classes handle business logic and interactions
\end{DoxyItemize}

Examples:\+
\begin{DoxyItemize}
\item {\ttfamily Main\+Window\+Builder} + {\ttfamily Main\+Window\+Delegate}
\item {\ttfamily System\+Setting\+Page\+Builder} + {\ttfamily System\+Setting\+Page\+Delegate}
\item {\ttfamily Work\+List\+Configuration\+Builder} + {\ttfamily Work\+List\+Configuration\+Delegate}
\end{DoxyItemize}

This pattern separates construction complexity from runtime behavior and provides clear extension points.\hypertarget{md__c_1_2_users_2altay_2_one_drive_2_projects_2etrek_2_c_l_a_u_d_e_autotoc_md12}{}\doxysubsection{\texorpdfstring{Service Initialization}{Service Initialization}}\label{md__c_1_2_users_2altay_2_one_drive_2_projects_2etrek_2_c_l_a_u_d_e_autotoc_md12}

\item Authentication service
\item RIS connections (Modality\+Worklist\+Manager)

\item Main window construction
