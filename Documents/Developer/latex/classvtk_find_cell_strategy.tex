\doxysubsection{Detailed Description}
helper class to manage the \doxylink{classvtk_point_set_a986526d35be66c4553b9521522935941}{vtk\+Point\+Set::\+\+Find\+Cell()} method 

\doxylink{classvtk_find_cell_strategy}{vtk\+Find\+Cell\+Strategy} is a helper class to manage the use of locators for locating cells containing a query point x\+[3]\+, the so-\/called \doxylink{classvtk_find_cell_strategy_a6bacf760fab8061122436b7eceff1b6d}{Find\+Cell()} method. \doxylink{requirements_The}{The} use of \doxylink{classvtk_data_set_a2221c10d3c4cca44e82c5ef70e4e1cbd}{vtk\+Data\+Set::\+\+Find\+Cell()} is a common operation in applications such as streamline generation and probing. However, in some dataset types \doxylink{classvtk_find_cell_strategy_a6bacf760fab8061122436b7eceff1b6d}{Find\+Cell()} can be implemented very simply (e.\+g., \doxylink{classvtk_image_data}{vtk\+Image\+Data}) while in other datasets it is a complex operation requiring supplemental objects like locators to perform efficiently. In particular, \doxylink{classvtk_point_set}{vtk\+Point\+Set} and its subclasses (like \doxylink{classvtk_unstructured_grid}{vtk\+Unstructured\+Grid}) require complex strategies to efficiently implement the \doxylink{classvtk_find_cell_strategy_a6bacf760fab8061122436b7eceff1b6d}{Find\+Cell()} operation. Subclasses of the abstract \doxylink{classvtk_find_cell_strategy}{vtk\+Find\+Cell\+Strategy} implement several of these strategies.

\doxylink{requirements_The}{The} are two key methods to this class and subclasses. \doxylink{requirements_The}{The} \doxylink{classvtk_find_cell_strategy_a94de77e1140c911cb8aae99ef39547a3}{Initialize()} method negotiates with an input dataset to define the locator to use:\+ either a locator associated with the input dataset, or possibly an alternative locator defined by the strategy (subclasses of \doxylink{classvtk_find_cell_strategy}{vtk\+Find\+Cell\+Strategy} do this). \doxylink{requirements_The}{The} second important method, \doxylink{classvtk_find_cell_strategy_a6bacf760fab8061122436b7eceff1b6d}{Find\+Cell()} mimics \doxylink{classvtk_data_set_a2221c10d3c4cca44e82c5ef70e4e1cbd}{vtk\+Data\+Set::\+\+Find\+Cell()} and can be used in place of it.

Note that \doxylink{classvtk_find_cell_strategy}{vtk\+Find\+Cell\+Strategy} is in general not thread-\/safe as the strategies contain state used to accelerate the search process. Hence if multiple threads are attempting to invoke \doxylink{classvtk_find_cell_strategy_a6bacf760fab8061122436b7eceff1b6d}{Find\+Cell()}, each thread needs to have its own instance of the \doxylink{classvtk_find_cell_strategy}{vtk\+Find\+Cell\+Strategy}.

Return the closest point within a specified radius and the cell which is closest to the point x. \doxylink{requirements_The}{The} closest point is somewhere on a cell, it need not be one of the vertices of the cell. This method returns 1 if a point is found within the specified radius. If there are no cells within the specified radius, the method returns 0 and the values of closest\+Point, cell\+Id, sub\+Id, and dist2 are undefined. This version takes in a \doxylink{classvtk_generic_cell}{vtk\+Generic\+Cell} to avoid allocating and deallocating the cell. This is much faster than the version which does not take a \texorpdfstring{$\ast$}{*}cell, especially when this function is called many times in a row such as by a for loop, where the allocation and dealloction can be done only once outside the for loop. If a closest point is found, "{}cell"{} contains the points and pt\+Ids for the cell "{}cell\+Id"{} upon exit. If a closest point is found, inside returns the return value of the Evaluate\+Position call to the closest cell; inside(=1) or outside(=0).
