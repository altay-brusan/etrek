\doxysubsection{Detailed Description}
abstract class defines interface between the widget and widget representation classes 

This class is used to define the API for, and partially implement, a representation for different types of widgets. Note that the widget representation (i.\+e., subclasses of \doxylink{classvtk_widget_representation}{vtk\+Widget\+Representation}) are a type of \doxylink{classvtk_prop}{vtk\+Prop}; meaning that they can be associated with a \doxylink{classvtk_renderer}{vtk\+Renderer} end embedded in a scene like any other \doxylink{classvtk_actor}{vtk\+Actor}. However, \doxylink{classvtk_widget_representation}{vtk\+Widget\+Representation} also defines an API that enables it to be paired with a subclass \doxylink{classvtk_abstract_widget}{vtk\+Abstract\+Widget}, meaning that it can be driven by a widget, serving to represent the widget as the widget responds to registered events.

\doxylink{requirements_The}{The} API defined here should be regarded as a guideline for implementing widgets and widget representations. Widget behavior is complex, as is the way the representation responds to the registered widget events, so the API may vary from widget to widget to reflect this complexity.

Clients of VTK, like Para\+View, need a uniform way to set colors on widgets. Most widgets have standard color setters -\/ new widgets should follow this pattern. \doxylink{requirements_The}{The} intended use of these colors is as follows:\+ \texorpdfstring{$\vert$}{|} Color \texorpdfstring{$\vert$}{|} Description \texorpdfstring{$\vert$}{|} \texorpdfstring{$\vert$}{|} -\/-\/-\/-\/-\/-\/-\/-\/--- \texorpdfstring{$\vert$}{|} -\/-\/-\/-\/-\/-\/-\/-\/--- \texorpdfstring{$\vert$}{|} \texorpdfstring{$\vert$}{|} {\ttfamily Handle\+Color} \texorpdfstring{$\vert$}{|} Widget handles that are available to interact with via click+drag. \texorpdfstring{$\vert$}{|} \texorpdfstring{$\vert$}{|} {\ttfamily Interaction\+Color} \texorpdfstring{$\vert$}{|} Widget handles the user is interacting with (via a click+drag) or hovering over. \texorpdfstring{$\vert$}{|} \texorpdfstring{$\vert$}{|} {\ttfamily Foreground\+Color} \texorpdfstring{$\vert$}{|} Widget elements meant to contrast with the background and which are not interactive. \texorpdfstring{$\vert$}{|}

When hovering, the {\ttfamily Interaction\+Color} can also be used to show which parts of the widget will change if this handle is dragged. For instance, using the {\ttfamily \doxylink{classvtk_display_sized_implicit_plane_representation}{vtk\+Display\+Sized\+Implicit\+Plane\+Representation}}, hovering the axis also displays the plane disc in the {\ttfamily Interaction\+Color}, to show it will change when the axis is rotated.

\doxylink{requirements_The}{The} separation of the widget event handling and representation enables users and developers to create new appearances for the widget. It also facilitates parallel processing, where the client application handles events, and remote representations of the widget are slaves to the client (and do not handle events).
