\subsubsection*{template$<$typename R, typename... Args$>$\newline
class vtk\+Threaded\+Task\+Queue$<$ R, Args $>$}
simple threaded task queue 

\doxylink{classvtk_threaded_task_queue}{vtk\+Threaded\+Task\+Queue} provides a simple task queue that can use threads to execute individual tasks. It is intended for use applications such as data compression, encoding etc. where the task may be completed concurrently without blocking the main thread.

\doxylink{classvtk_threaded_task_queue}{vtk\+Threaded\+Task\+Queue}\textquotesingle{}s API is intended to called from the same main thread. \doxylink{requirements_The}{The} constructor defines the work (or task) to be performed. {\ttfamily \doxylink{classvtk_threaded_task_queue_a7e3a880c994d27783ab65647437e67af}{Push}} allows the caller to enqueue a task with specified input arguments. \doxylink{requirements_The}{The} call will return immediately without blocking. \doxylink{requirements_The}{The} task is enqueued and will be executed concurrently when resources become available. {\ttfamily \doxylink{classvtk_threaded_task_queue_a4a96fc1953b86c5fa1b8cec2a04e88ba}{Pop}} will block until the result is available. To avoid waiting for results to be available, use {\ttfamily \doxylink{classvtk_threaded_task_queue_a57f3fdbb2111e802143401e62acf74af}{Try\+Pop}}.

\doxylink{requirements_The}{The} constructor allows mechanism to customize the queue. {\ttfamily strict\+\_\+ordering} implies that results should be popped in the same order that tasks were pushed without dropping any task. If the caller is only concerned with obtaining the latest available result where intermediate results that take longer to compute may be dropped, then {\ttfamily strict\+\_\+ordering} can be set to {\ttfamily false}.

{\ttfamily max\+\_\+concurrent\+\_\+tasks} controls how many threads are used to process tasks in the queue. Default is same as {\ttfamily vtk\+Multi\+Threader::\+\+Get\+Global\+Default\+Number\+Of\+Threads()}.

{\ttfamily buffer\+\_\+size} indicates how many tasks may be queued for processing. Default is infinite size. If a positive number is provided, then pushing additional tasks will result in discarding of older tasks that haven\textquotesingle{}t begun processing from the queue. Note, this does not impact tasks that may already be in progress. Also, if {\ttfamily strict\+\_\+ordering} is true, this is ignored; the buffer\+\_\+size will be set to unlimited.
