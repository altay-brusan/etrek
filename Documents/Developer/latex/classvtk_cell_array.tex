\doxysubsection{Detailed Description}
object to represent cell connectivity 

\doxylink{classvtk_cell_array}{vtk\+Cell\+Array} stores dataset topologies as an explicit connectivity table listing the point ids that make up each cell.

Internally, the connectivity table is represented as two arrays:\+ Offsets and Connectivity.

Offsets is an array of \+[num\+Cells+1]\+ values indicating the index in the Connectivity array where each cell\textquotesingle{}s points start. \doxylink{requirements_The}{The} last value is always the length of the Connectivity array.

\doxylink{requirements_The}{The} Connectivity array stores the lists of point ids for each cell.

Thus, for a dataset consisting of 2 triangles, a quad, and a line, the internal arrays will appear as follows:\+

\end{DoxyCode}


While this class provides traversal methods (the legacy \doxylink{classvtk_cell_array_a6c1b282e364ced768fc6902eba2883c4}{Init\+Traversal()}, \doxylink{classvtk_cell_array_a12550b9db4de79a64491cff4df0dd8eb}{Get\+Next\+Cell()} methods, and the newer method \doxylink{classvtk_cell_array_a1ab9347687f5ce38b378f26d2390d1c1}{Get\+Cell\+At\+Id()}) these are in general not thread-\/safe. Whenever possible it is preferable to use a local thread-\/safe, \doxylink{classvtk_cell_array_iterator}{vtk\+Cell\+Array\+Iterator} object, which can be obtained via:\+


\begin{DoxyCode}{0}

\end{DoxyCode}
 (Note however that depending on the type and structure of internal storage, a cell array iterator may be significantly slower than direct traversal over the cell array due to extra data copying. Factors of 3-\/4X are not uncommon. See \doxylink{classvtk_cell_array_iterator}{vtk\+Cell\+Array\+Iterator} for more information. Also note that an iterator may become invalid if the internal \doxylink{classvtk_cell_array}{vtk\+Cell\+Array} storage is modified.)

Other methods are also available for allocation and memory-\/related management; insertion of new cells into the \doxylink{classvtk_cell_array}{vtk\+Cell\+Array}; and limited editing operations such as replacing one cell with a new cell of the same size.

\doxylink{requirements_The}{The} internal arrays may store either 32-\/ or 64-\/bit values, though most of the API will prefer to use vtk\+Id\+Type to refer to items in these arrays. This enables significant memory savings when vtk\+Id\+Type is 64-\/bit, but 32 bits are sufficient to store all of the values in the connectivity table. Using 64-\/bit storage with a 32-\/bit vtk\+Id\+Type is permitted, but values too large to fit in a 32-\/bit signed integer will be truncated when accessed through the API. (\doxylink{requirements_The}{The} particular internal storage type has implications on performance depending on vtk\+Id\+Type. If the internal storage is equivalent to vtk\+Id\+Type, then methods that return pointers to arrays of point ids can share the internal storage; otherwise a copy of internal memory must be performed.)
