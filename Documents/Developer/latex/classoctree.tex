\subsubsection*{template$<$typename T\+\_\+, int d\+\_\+ = 3, typename A\+\_\+ = std::\+allocator$<$\+T\+\_\+$>$$>$\newline
class octree$<$ T\+\_\+, d\+\_\+, A\+\_\+ $>$}
An n-\/dimensional octree. Perhaps it should be named a tttntree (two-\/to-\/the n tree)? 

This templated class provides an n-\/dimensional binary tree, storing an object whose type is specified by the first template parameter at each node (whether or not that node is a leaf). \doxylink{requirements_The}{The} second template parameter is an integer constant specifying the dimension of the tree. \doxylink{requirements_The}{The} final template parameter takes an allocator object just as the STL does.

\doxylink{requirements_The}{The} tree itself stores the center and overall bounds of the root node; the nodes themselves do not contain any information on the geometry. If needed, it can be derived from an \doxylink{classoctree__path}{octree\+\_\+path} object referring to the node or stored in the template class at each node for fast access. This makes the class useful for storing abstract trees with minimal overhead as well as trees embedded in a metric space.

Access to entries in the tree is provided by \doxylink{classoctree__cursor}{octree\+\_\+cursor} and \doxylink{classoctree__iterator}{octree\+\_\+iterator} objects, both of which inherit \doxylink{classoctree__path}{octree\+\_\+path}. An \doxylink{classoctree__path}{octree\+\_\+path} stores a vector of integers describing a descent from the root node to a particular child node of the octree. Since each node of a $d$-\/dimensional tree has $2^d$ children, the integers in the vector will all be in $\{0,\ldots,2^d-1\}$.

\doxylink{requirements_The}{The} \doxylink{classoctree__cursor}{octree\+\_\+cursor} class provides a free-\/form way to visit nodes in the octree; it does not behave like an iterator that guarantees each node will be visited once. Instead, it provides a way to move up, down, and across the tree from any location. This makes it useful for local queries that do not need to traverse the entire tree.

\doxylink{requirements_The}{The} \doxylink{classoctree__iterator}{octree\+\_\+iterator} class simply traverses the tree in depth-\/first order and can be configured to visit only leaf nodes or to include all nodes.

Iterator based access. 

Iterators come in const and non-\/const versions as well as versions that visit all nodes or just leaf nodes. By default, only leaf nodes are visited.

You may add or remove children while iterating with some caveats. When adding children, any iterator currently referencing the node to which children were added will reference the first child node when incremented. Iterators confined to leaf nodes may reference non-\/leaf nodes when refinement occurs between increments/\+decrements. When removing children from node {\itshape A}, any iterators pointing to grandchildren of {\itshape A} will become invalid. Iterators pointing to children of {\itshape A} may not be dereferenced but may be incremented or decremented safely.
