\doxysubsection{Detailed Description}
base class for writing debug output to a console 

This class is used to encapsulate all text output, so that it will work with operating systems that have a stdout and stderr, and ones that do not. (i.\+e windows does not). Sub-\/classes can be provided which can redirect the output to a window.

\doxysubsubsection{\texorpdfstring{DisplayModes}{DisplayModes}}
{\footnotesize\ttfamily \label{classvtk_output_window_a396e3d4d4c208c7b1fab6e4ba7a63e14} 
enum \doxymbox{\hyperlink{classvtk_output_window_a396e3d4d4c208c7b1fab6e4ba7a63e14}{vtk\+Output\+Window::\+\+Display\+Modes}}}

Flag indicates how the \doxylink{classvtk_output_window}{vtk\+Output\+Window} handles displaying of text to {\ttfamily stderr} /\+ {\ttfamily stdout}. Default is {\ttfamily DEFAULT} except in {\ttfamily \doxylink{classvtk_win32_output_window}{vtk\+Win32\+Output\+Window}} where on non dashboard runs, the default is {\ttfamily NEVER}.

{\ttfamily NEVER} indicates that the messages should never be forwarded to the standard output/\+error streams.

{\ttfamily ALWAYS} will result in error/\+warning/\+debug messages being posted to the standard error stream, while text messages to standard output stream.

{\ttfamily ALWAYS\+\_\+\+STDERR} will result in all messages being posted to the standard error stream (this was default behavior in VTK 8.\+1 and earlier).

{\ttfamily DEFAULT} is similar to {\ttfamily ALWAYS} except when logging is enabled. If logging is enabled, messages posted to the output window using VTK error/\+warning macros such as {\ttfamily vtk\+Error\+Macro}, {\ttfamily vtk\+Warning\+Macro} etc. will not posted on any of the output streams. This is done to avoid duplicate messages on these streams since these macros also result in add items to the log.

\begin{DoxyNote}{Note}
\doxylink{classvtk_string_output_window}{vtk\+String\+Output\+Window} does not result this flag as is never forwards any text to the output streams. 
\end{DoxyNote}
