\doxysubsection{Detailed Description}
Encapsulate traversal logic for \doxylink{classvtk_cell_array}{vtk\+Cell\+Array}. 

This is iterator for thread-\/safe traversal of a \doxylink{classvtk_cell_array}{vtk\+Cell\+Array}. It provides random access and forward iteration. Typical usage for forward iteration looks like:\+

Here {\itshape cell\+Id} is the id of the ith cell in the \doxylink{classvtk_cell_array}{vtk\+Cell\+Array}; {\itshape num\+Cell\+Pts} is the number of points defining the cell represented as vtk\+Id\+Type; and {\itshape cell\+Pts} is a pointer to the point ids defined as vtk\+Id\+Type const\texorpdfstring{$\ast$}{*}\&.

Internally the iterator may copy data from the \doxylink{classvtk_cell_array}{vtk\+Cell\+Array}, or reference the internal \doxylink{classvtk_cell_array}{vtk\+Cell\+Array} storage. This depends on the relationship of vtk\+Id\+Type to the type and structure of internal storage. If the type of storage is the same as vtk\+Id\+Type, and the storage is a single-\/component AOS array (i.\+e., a 1D array), then shared access to the \doxylink{classvtk_cell_array}{vtk\+Cell\+Array} storage is provided. Otherwise, the data from storage is copied into an internal iterator buffer. (Of course copying is slower and can result in 3-\/4x reduction in traversal performance. On the other hand, the \doxylink{classvtk_cell_array}{vtk\+Cell\+Array} can use the appropriate storage to save memory, perform zero-\/copy, and/\+or efficiently represent the cell connectivity information.) Note that referencing internal \doxylink{classvtk_cell_array}{vtk\+Cell\+Array} storage has implications on the validity of the iterator. If the underlying \doxylink{classvtk_cell_array}{vtk\+Cell\+Array} storage changes while iterating, and the iterator is referencing this storage, unpredictable and catastrophic results are likely -\/ hence do not modify the \doxylink{classvtk_cell_array}{vtk\+Cell\+Array} while iterating.
