\doxysubsection{Detailed Description}
quickly locate points in 3-\/space 

\doxylink{classvtk_static_point_locator}{vtk\+Static\+Point\+Locator} is a spatial search object to quickly locate points in 3D. \doxylink{classvtk_static_point_locator}{vtk\+Static\+Point\+Locator} works by dividing a specified region of space into a regular array of cuboid buckets, and then keeping a list of points that lie in each bucket. Typical operation involves giving a position in 3D and finding the closest point; or finding the N closest points.

\doxylink{classvtk_static_point_locator}{vtk\+Static\+Point\+Locator} is an accelerated version of \doxylink{classvtk_point_locator}{vtk\+Point\+Locator}. It is threaded (via \doxylink{classvtk_s_m_p_tools}{vtk\+SMPTools}), and supports one-\/time static construction (i.\+e., incremental point insertion is not supported). If you need to incrementally insert points, use the \doxylink{classvtk_point_locator}{vtk\+Point\+Locator} or its kin to do so.

\begin{DoxyWarning}{Warning}
This class is templated. It may run slower than serial execution if the code is not optimized during compilation. Build in Release or Release\+With\+Debug\+Info.

Make sure that you review the documentation for the superclasses vtk\+Abstact\+Point\+Locator and \doxylink{classvtk_locator}{vtk\+Locator}. In particular the Automatic data member can be used to automatically determine divisions based on the average number of points per bucket.

Other types of spatial locators have been developed such as octrees and kd-\/trees. These are often more efficient for the operations described here.

Frequently \doxylink{classvtk_static_point_locator}{vtk\+Static\+Point\+Locator} is used in lieu of \doxylink{classvtk_point_locator}{vtk\+Point\+Locator}. They are very similar in terms of algorithmic approach, however \doxylink{classvtk_static_cell_locator}{vtk\+Static\+Cell\+Locator} is threaded and is typically much faster for a large number of points (on the order of 3-\/5x faster). For small numbers of points, \doxylink{classvtk_point_locator}{vtk\+Point\+Locator} is just as fast as \doxylink{classvtk_static_point_locator}{vtk\+Static\+Point\+Locator}.
\end{DoxyWarning}

Point merging is inherently an order-\/dependent process. Because naive threaded execution can non-\/deterministically change the ordering of merged points, threaded point merging for tolerances != 0.\+0 requires some level of serialization of the merging process to produce deterministic results. POINT\+\_\+\+ORDER is completely serialized:\+ two points with ids p0,p1 are merged if they are within tolerance of one another, with p1-\/\texorpdfstring{$>$}{>}p0 (p1 merged to p0) if p0\texorpdfstring{$<$}{<}p1. IN BIN\+\_\+\+ORDER, a threaded checkerboarding approach is used so that p1-\/\texorpdfstring{$>$}{>}p0 when p0\texorpdfstring{$<$}{<}p1 in the local bin neighborhood and p1 not yet merged.
