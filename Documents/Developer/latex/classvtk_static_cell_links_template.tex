\doxysubsection{Detailed Description}
\subsubsection*{template$<$typename TIds$>$\newline
class vtk\+Static\+Cell\+Links\+Template$<$ TIds $>$}
object represents upward pointers from points to list of cells using each point (template implementation) 

\doxylink{classvtk_static_cell_links_template}{vtk\+Static\+Cell\+Links\+Template} is a supplemental object to \doxylink{classvtk_cell_array}{vtk\+Cell\+Array} and \doxylink{classvtk_cell_types}{vtk\+Cell\+Types}, enabling access to the list of cells using each point. \doxylink{classvtk_static_cell_links_template}{vtk\+Static\+Cell\+Links\+Template} is an array of links, each link represents a list of cell ids using a particular point. \doxylink{requirements_The}{The} information provided by this object can be used to determine neighbors (e.\+g., face neighbors, edge neighbors)and construct other local topological information. This class is a faster implementation of \doxylink{classvtk_cell_links}{vtk\+Cell\+Links}. However, it cannot be incrementally constructed; it is meant to be constructed once (statically) and must be rebuilt if the cells change.

This is a templated implementation for \doxylink{classvtk_static_cell_links}{vtk\+Static\+Cell\+Links}. \doxylink{requirements_The}{The} reason for the templating is to gain performance and reduce memory by using smaller integral types to represent ids. For example, if the maximum id can be represented by an int (as compared to a vtk\+Id\+Type), it is possible to reduce memory requirements by half and increase performance. This templated class can be used directly; alternatively the non-\/templated class \doxylink{classvtk_static_cell_links}{vtk\+Static\+Cell\+Links} can be used for convenience; although it uses vtk\+Id\+Type and so will lose some speed and memory advantages.
