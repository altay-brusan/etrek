\doxysubsection{Detailed Description}
abstract API for pickers that can pick an instance of \doxylink{classvtk_prop}{vtk\+Prop} 

\doxylink{classvtk_abstract_prop_picker}{vtk\+Abstract\+Prop\+Picker} is an abstract superclass for pickers that can pick an instance of \doxylink{classvtk_prop}{vtk\+Prop}. Some pickers, like \doxylink{classvtk_world_point_picker}{vtk\+World\+Point\+Picker} (not a subclass of this class), cannot identify the prop that is picked. Subclasses of \doxylink{classvtk_abstract_prop_picker}{vtk\+Abstract\+Prop\+Picker} return a prop in the form of a \doxylink{classvtk_assembly_path}{vtk\+Assembly\+Path} when a pick is invoked. Note that an \doxylink{classvtk_assembly_path}{vtk\+Assembly\+Path} contain a list of vtk\+Assembly\+Nodes, each of which in turn contains a reference to a \doxylink{classvtk_prop}{vtk\+Prop} and a 4x4 transformation matrix. \doxylink{requirements_The}{The} path fully describes the entire pick path, so you can pick assemblies or portions of assemblies, or just grab the tail end of the \doxylink{classvtk_assembly_path}{vtk\+Assembly\+Path} (which is the picked prop).

\begin{DoxyWarning}{Warning}
Because a \doxylink{classvtk_prop}{vtk\+Prop} can be placed into different assemblies, or even in different leaf positions of the same assembly, the \doxylink{classvtk_assembly_path}{vtk\+Assembly\+Path} is used to fully qualify exactly which use of the \doxylink{classvtk_prop}{vtk\+Prop} was picked, including its position (since \doxylink{classvtk_assembly_path}{vtk\+Assembly\+Path} includes a transformation matrix per node).

\doxylink{requirements_The}{The} class returns information about picked actors, props, etc. Note that what is returned by these methods is the top level of the assembly path. This can cause a lot of confusion! For example, if you pick a \doxylink{classvtk_assembly}{vtk\+Assembly}, and the returned \doxylink{classvtk_assembly_path}{vtk\+Assembly\+Path} has as a leaf a \doxylink{classvtk_actor}{vtk\+Actor}, then if you invoke \doxylink{classvtk_abstract_prop_picker_ac7675cabcc4777c82651f97c5379ce59}{Get\+Actor()}, you will get NULL, even though an actor was indeed picked. (\doxylink{classvtk_abstract_prop_picker_a8d5112a05d0983be5f65bb0e0414bdff}{Get\+Assembly()} will return something.) Note that the safest thing to do is to do a \doxylink{classvtk_abstract_prop_picker_abe56da95ba350675d46fadfb2d719ba6}{Get\+View\+Prop()}, which will always return something if something was picked. A better way to manage picking is to work with \doxylink{classvtk_assembly_path}{vtk\+Assembly\+Path}, since this completely defines the pick path from top to bottom in a assembly hierarchy, and avoids confusion when the same prop is used in different assemblies.

\doxylink{requirements_The}{The} returned assembly paths refer to assembly nodes that in turn refer to \doxylink{classvtk_prop}{vtk\+Prop} and vtk\+Matrix. This association to \doxylink{classvtk_prop}{vtk\+Prop} is not a reference counted association, meaning that dangling references are possible if you do a pick, get an assembly path, and then delete a \doxylink{classvtk_prop}{vtk\+Prop}. (Reason:\+ assembly paths create many self-\/referencing loops that destroy reference counting.)
\end{DoxyWarning}
