\subsubsection*{template$<$typename ArrayT$>$\newline
class vtk\+Data\+Array\+Accessor$<$ Array\+T $>$}
Efficient templated access to \doxylink{classvtk_data_array}{vtk\+Data\+Array}. 

\begin{DoxyWarning}{Warning}
\doxylink{structvtk_data_array_accessor}{vtk\+Data\+Array\+Accessor} has been replaced by the much easier to use range facilities \doxylink{namespacevtk_ab3b536698b4a3d1ab80d9d7ba21fd5e9}{vtk::\+\+Data\+Array\+Tuple\+Range} and \doxylink{namespacevtk_abb6756380d24cda3ea3a74fdcbdf8de1}{vtk::\+\+Data\+Array\+Value\+Range}, defined in \doxylink{vtk_data_array_range_8h}{vtk\+Data\+Array\+Range.\+h}. This accessor class shouldn\textquotesingle{}t need to be used directly.
\end{DoxyWarning}
\doxylink{structvtk_data_array_accessor}{vtk\+Data\+Array\+Accessor} provides access to data stored in a \doxylink{classvtk_data_array}{vtk\+Data\+Array}. It is intended to be used in conjunction with vtk\+Array\+Dispatcher.

A more detailed description of this class and related tools can be found \href{https://docs.vtk.org/en/latest/design_documents/array_dispatch.html}{\texttt{here}}.

\doxylink{requirements_The}{The} goal of this helper template is to allow developers to write a single templated worker function that will generates code to use the efficient typed APIs provided by \doxylink{classvtk_generic_data_array}{vtk\+Generic\+Data\+Array} when the array type is known, but fallback to the slower \doxylink{classvtk_data_array}{vtk\+Data\+Array} virtual double API if needed.

This can be used to reduce template-\/explosion issues by restricting the \doxylink{classvtk_array_dispatch}{vtk\+Array\+Dispatch} call to only dispatch a few common cases/\+array types, and route all other arrays through a slower implementation using \doxylink{classvtk_data_array}{vtk\+Data\+Array}\textquotesingle{}s API. With \doxylink{structvtk_data_array_accessor}{vtk\+Data\+Array\+Accessor}, a single templated worker function can be used to generate both.

Note that while this interface provides both component-\/wise and tuple access, the tuple methods are discouraged as they are significantly slower as they copy data into a temporary array, and prevent many advanced compiler optimizations that are possible when using the component accessors. In other words, prefer the methods that operate on a single component instead of an entire tuple when performance matters.

We define Worker::\+operator() as the templated worker function, restricting all data accesses to go through the \textquotesingle{}accessor\textquotesingle{} object (methods like Get\+Number\+Of\+Tuples, Get\+Number\+Of\+Components, etc should be called on the array itself).

This worker is passed into an array dispatcher, which tests \textquotesingle{}array\textquotesingle{} to see if it can figure out the array subclass. If it does, Worker is instantiated with ArrayT set to the array\textquotesingle{}s subclass, resulting in efficient code. If Dispatch::\+\+Execute returns false (meaning the array type is not recognized), the worker is executed using the \doxylink{classvtk_data_array}{vtk\+Data\+Array} pointer. While slower, this ensures that less-\/common cases will still be handled -- all from one worker function template.
