\doxysubsection{Detailed Description}
Custom functions for memory handling. 

A pointer to \doxylink{structlzma__allocator}{lzma\+\_\+allocator} may be passed via \doxylink{structlzma__stream}{lzma\+\_\+stream} structure to liblzma, and some advanced functions take a pointer to \doxylink{structlzma__allocator}{lzma\+\_\+allocator} as a separate function argument. \doxylink{requirements_The}{The} library will use the functions specified in \doxylink{structlzma__allocator}{lzma\+\_\+allocator} for memory handling instead of the default malloc() and free(). C++ users should note that the custom memory handling functions must not throw exceptions.

Single-\/threaded mode only:\+ liblzma doesn\textquotesingle{}t make an internal copy of \doxylink{structlzma__allocator}{lzma\+\_\+allocator}. Thus, it is OK to change these function pointers in the middle of the coding process, but obviously it must be done carefully to make sure that the replacement \textquotesingle{}free\textquotesingle{} can deallocate memory allocated by the earlier \textquotesingle{}alloc\textquotesingle{} function(s).

Multithreaded mode:\+ liblzma might internally store pointers to the \doxylink{structlzma__allocator}{lzma\+\_\+allocator} given via the \doxylink{structlzma__stream}{lzma\+\_\+stream} structure. \doxylink{requirements_The}{The} application must not change the allocator pointer in \doxylink{structlzma__stream}{lzma\+\_\+stream} or the contents of the pointed \doxylink{structlzma__allocator}{lzma\+\_\+allocator} structure until lzma\+\_\+end() has been used to free the memory associated with that \doxylink{structlzma__stream}{lzma\+\_\+stream}. \doxylink{requirements_The}{The} allocation functions might be called simultaneously from multiple threads, and thus they must be thread safe.

\doxylink{requirements_The}{The} allocator should not waste time zeroing the allocated buffers. This is not only about speed, but also memory usage, since the operating system kernel doesn\textquotesingle{}t necessarily allocate the requested memory in physical memory until it is actually used. With small input files, liblzma may actually need only a fraction of the memory that it requested for allocation.

\begin{DoxyNote}{Note}
