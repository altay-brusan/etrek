\doxysubsection{Detailed Description}
Variable-\/length integer handling. 

\begin{DoxyNote}{Note}
Never include this file directly. Use \texorpdfstring{$<$}{<}\doxylink{lzma_8h}{lzma.\+h}\texorpdfstring{$>$}{>} instead.
\end{DoxyNote}
In the .xz format, most integers are encoded in a variable-\/length representation, which is sometimes called little endian base-\/128 encoding. This saves space when smaller values are more likely than bigger values.

\doxylink{requirements_The}{The} encoding scheme encodes seven bits to every byte, using minimum number of bytes required to represent the given value. Encodings that use non-\/minimum number of bytes are invalid, thus every integer has exactly one encoded representation. \doxylink{requirements_The}{The} maximum number of bits in a VLI is 63, thus the vli argument must be less than or equal to UINT64\+\_\+\+MAX /\+ 2. You should use LZMA\+\_\+\+VLI\+\_\+\+MAX for clarity.

Variable-\/length integer type. 

Valid VLI values are in the range \+[0, LZMA\+\_\+\+VLI\+\_\+\+MAX]\+. Unknown value is indicated with LZMA\+\_\+\+VLI\+\_\+\+UNKNOWN, which is the maximum value of the underlying integer type.

\doxylink{vli_8h_a1dbc0ffc3e72748f64df8f7f71898272}{lzma\+\_\+vli} will be uint64\+\_\+t for the foreseeable future. If a bigger size is needed in the future, it is guaranteed that 2 \texorpdfstring{$\ast$}{*} LZMA\+\_\+\+VLI\+\_\+\+MAX will not overflow \doxylink{vli_8h_a1dbc0ffc3e72748f64df8f7f71898272}{lzma\+\_\+vli}. This simplifies integer overflow detection.

Decode a variable-\/length integer.

This function has two modes:\+ single-\/call and multi-\/call. Single-\/call mode encodes the whole integer at once; it is an error if the output buffer is too small. Multi-\/call mode saves the position in \texorpdfstring{$\ast$}{*}vli\+\_\+pos, and thus it is possible to continue encoding if the buffer becomes full before the whole integer has been encoded.
