\doxysubsection{Detailed Description}
\subsubsection*{template$<$class Implementation, class Cell\+Iterator = vtk\+Mapped\+Unstructured\+Grid\+Cell\+Iterator$<$\+Implementation$>$$>$\newline
class vtk\+Mapped\+Unstructured\+Grid$<$ Implementation, Cell\+Iterator $>$}
Allows datasets with arbitrary storage layouts to be used with VTK. 

This class fulfills the \doxylink{classvtk_unstructured_grid_base}{vtk\+Unstructured\+Grid\+Base} API while delegating to a arbitrary implementation of the dataset topology. \doxylink{requirements_The}{The} purpose of \doxylink{classvtk_mapped_unstructured_grid}{vtk\+Mapped\+Unstructured\+Grid} is to allow external data structures to be used directly in a VTK pipeline, e.\+g. for in-\/situ analysis of a running simulation.

When introducing an external data structure into VTK, there are 3 principle components of the dataset to consider:\+
\begin{DoxyItemize}
\item Points
\item Cells (topology)
\item Point/\+\+Cell attributes
\end{DoxyItemize}

Points and attributes can be handled by subclassing \doxylink{classvtk_mapped_data_array}{vtk\+Mapped\+Data\+Array} and implementing that interface to adapt the external data structures into VTK. \doxylink{requirements_The}{The} \doxylink{classvtk_mapped_data_array}{vtk\+Mapped\+Data\+Array} subclasses can then be used as the \doxylink{classvtk_points}{vtk\+Points}\textquotesingle{}s Data member (for points/\+nodes) or added directly to \doxylink{classvtk_point_data}{vtk\+Point\+Data}, \doxylink{classvtk_cell_data}{vtk\+Cell\+Data}, or \doxylink{classvtk_field_data}{vtk\+Field\+Data} for attribute information. Filters used in the pipeline will need to be modified to remove calls to vtk\+Data\+Array::\+\+Get\+Void\+Pointer and use a suitable \doxylink{classvtk_array_dispatch}{vtk\+Array\+Dispatch} instead.

Introducing an arbitrary topology implementation into VTK requires the use of the \doxylink{classvtk_mapped_unstructured_grid}{vtk\+Mapped\+Unstructured\+Grid} class. Unlike the data array counterpart, the mapped unstructured grid is not subclassed, but rather takes an adaptor class as a template argument. This is to allow cheap shallow copies of the data by passing the reference-\/counted implementation object to new instances of \doxylink{classvtk_mapped_unstructured_grid}{vtk\+Mapped\+Unstructured\+Grid}.

\doxylink{requirements_The}{The} implementation class should derive from \doxylink{classvtk_object}{vtk\+Object} (for reference counting) and implement the usual \doxylink{classvtk_object}{vtk\+Object} API requirements, such as a static \doxylink{classvtk_point_set_a794f947e23ffcf921cbfa7d7628ad3d2}{New()} method and Print\+Self function. \doxylink{requirements_The}{The} following methods must also be implemented:\+
