\doxysubsection{Detailed Description}
A flexible layout configurable with pattern string.

\doxylink{requirements_The}{The} goal of this class is to format a Internal\+Logging\+Event and return the results as a string. \doxylink{requirements_The}{The} results depend on the {\itshape conversion pattern}.

\doxylink{requirements_The}{The} conversion pattern is closely related to the conversion pattern of the printf function in C. A conversion pattern is composed of literal text and format control expressions called {\itshape conversion specifiers}.

{\itshape You are free to insert any literal text within the conversion pattern.}

Each conversion specifier starts with a percent sign (\%\%) and is followed by optional {\itshape format modifiers} and a {\itshape conversion character}. \doxylink{requirements_The}{The} conversion character specifies the type of data, e.\+g. \doxylink{classdcmtk_1_1log4cplus_1_1_logger}{Logger}, \doxylink{_third_party_libraries_2dcmtk_2include_2dcmtk_2oflog_2_log_level_8h_a0b1dd55c81b77bb59e5adcd343f393d7}{Log\+Level}, date, thread name. \doxylink{requirements_The}{The} format modifiers control such things as field width, padding, left and right justification. \doxylink{requirements_The}{The} following is a simple example.

Let the conversion pattern be {\bfseries{"{}\%-\/5p \+[\%t]\+:\+ \%m\%n"{}}} and assume that the log4cplus environment was set to use a \doxylink{classdcmtk_1_1log4cplus_1_1_pattern_layout}{Pattern\+Layout}. Then the statements {\ttfamily 
\begin{DoxyPre}
\doxylink{classdcmtk_1_1log4cplus_1_1_logger}{Logger} root = \doxylink{classdcmtk_1_1log4cplus_1_1_logger_a03f4ce5da52d926a06bc5ebc19f4807f}{Logger.getRoot()};
DCMTK\_LOG4CPLUS\_DEBUG(root, "{}Message 1"{});
DCMTK\_LOG4CPLUS\_WARN(root, "{}Message 2"{});
\end{DoxyPre}
} would yield the output {\ttfamily 
\begin{DoxyPre}
DEBUG [main]: Message 1
WARN  [main]: Message 2
\end{DoxyPre}
}

Note that there is no explicit separator between text and conversion specifiers. \doxylink{requirements_The}{The} pattern parser knows when it has reached the end of a conversion specifier when it reads a conversion character. In the example above the conversion specifier {\bfseries{"{}\%-\/5p"{}}} means the \doxylink{_third_party_libraries_2dcmtk_2include_2dcmtk_2oflog_2_log_level_8h_a0b1dd55c81b77bb59e5adcd343f393d7}{Log\+Level} of the logging event should be left justified to a width of five characters.

{\bfseries{"{}\%\%"{}}}

\doxylink{requirements_The}{The} sequence "{}\%\%"{} outputs a single percent sign.

By default the relevant information is output as is. However, with the aid of format modifiers it is possible to change the minimum field width, the maximum field width and justification.

\doxylink{requirements_The}{The} optional format modifier is placed between the percent sign and the conversion character.

\doxylink{requirements_The}{The} first optional format modifier is the {\itshape left justification flag} which is just the minus (-\/) character. Then comes the optional {\itshape minimum field width} modifier. This is a decimal constant that represents the minimum number of characters to output. If the data item requires fewer characters, it is padded on either the left or the right until the minimum width is reached. \doxylink{requirements_The}{The} default is to pad on the left (right justify) but you can specify right padding with the left justification flag. \doxylink{requirements_The}{The} padding character is space. If the data item is larger than the minimum field width, the field is expanded to accommodate the data. \doxylink{requirements_The}{The} value is never truncated.

This behavior can be changed using the {\itshape maximum field width} modifier which is designated by a period followed by a decimal constant. If the data item is longer than the maximum field, then the extra characters are removed from the {\itshape beginning} of the data item and not from the end. For example, it the maximum field width is eight and the data item is ten characters long, then the first two characters of the data item are dropped. This behavior deviates from the printf function in C where truncation is done from the end.

Below are some examples of conversion patterns.


\begin{DoxyDescription}
\item[{\parbox[t]{\linewidth}{{\bfseries{"{}\%r \+[\%t]\+ \%-\/5p \%c \%x -\/ \%m\%n"{}}} }}]\hfill \\
This is essentially the TTCC layout.


\item[{\parbox[t]{\linewidth}{{\bfseries{"{}\%-\/6r \+[\%15.\+15t]\+ \%-\/5p \%30.\+30c \%x -\/ \%m\%n"{}}} }}]\hfill \\
Similar to the TTCC layout except that the relative time is right padded if less than 6 digits, thread name is right padded if less than 15 characters and truncated if longer and the logger name is left padded if shorter than 30 characters and truncated if longer.


\end{DoxyDescription}
