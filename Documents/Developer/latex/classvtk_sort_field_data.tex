\doxysubsection{Detailed Description}
provides a method for sorting field data 

\doxylink{classvtk_sort_field_data}{vtk\+Sort\+Field\+Data} is used to sort data, based on its value, or with an associated key, into either ascending or descending order. This is useful for operations like selection, or analysis, when evaluating and processing data.

This class, which extends the base functionality of \doxylink{classvtk_sort_data_array}{vtk\+Sort\+Data\+Array}, is used to sort field data and its various subclasses (\doxylink{classvtk_field_data}{vtk\+Field\+Data}, \doxylink{classvtk_data_set_attributes}{vtk\+Data\+Set\+Attributes}, \doxylink{classvtk_point_data}{vtk\+Point\+Data}, \doxylink{classvtk_cell_data}{vtk\+Cell\+Data}, etc.)

\begin{DoxyWarning}{Warning}
This class has been threaded with \doxylink{classvtk_s_m_p_tools}{vtk\+SMPTools}. Using TBB or other non-\/sequential type (set in the CMake variable VTK\+\_\+\+SMP\+\_\+\+IMPLEMENTATION\+\_\+\+TYPE) may improve performance significantly on multi-\/core machines.

\doxylink{requirements_The}{The} sort methods below are static, hence the sorting methods can be used without instantiating the class. All methods are thread safe.
\end{DoxyWarning}

In other words, if an array has n components, the kth component is used to sort the array and all of the other arrays in the field data. \doxylink{requirements_The}{The} order of the sorted data is goven by dir:\+ dir=0 means sort in ascending order; dir=1 means sort in descending order. Also note that the user can indicate whether the function returns the sort indices (return\+Indices=1). If the indices are returned, then the user takes ownership of the data and must delete it. Note that the indices are always in sorted (ascending) order, and indicate the final sorted position of the sort. So for example indices\+[0]\+=10 indicates that the original data in position 10 in the field, was moved to position 0 after the sort (i.\+e., position 0 is the smallest value). However, if sort direction dir=1, the indices do not change but the final shuffle of the data is in reverse order (note idx\+[n-\/1]\+ for n keys is the largest value). By default, return\+Indices=0.
