\doxylink{requirements_The}{The} “blit” operation means copying something (pixels) from one region in memory to another. This is a common Open\+GL operation:\+ check out the gl\+Blit\+Framebuffer Open\+GL method. VTK Open\+GL rasterizes 3D/\+2D geometry into color/\+depth attachments of an in-\/memory framebuffer:\+ in the graphics world, this is called offscreen rendering.

\doxylink{requirements_The}{The} Frame\+Blit\+Mode tells VTK where to copy the offscreen buffer. Either the default hardware framebuffer or the currently bound framebuffer. Here are the available modes:\+
\begin{DoxyItemize}
\item Blit\+To\+Hardware:\+ This mode blits to the default framebuffer managed by platform(Win32/\+\+X/\+\+Cocoa) render windows. This is the default mode when VTK is used through one of the platform render windows (with \doxylink{classvtk_render_window}{vtk\+Render\+Window}).
\item Blit\+To\+Current:\+ This mode blits to the currently bound framebuffer. You’ll need this when integrating VTK with other UI frameworks because these UI frameworks create/\+have their own framebuffers. This only blits the color buffer.
\item Blit\+To\+Current\+With\+Depth:\+ Almost the same as Blit\+To\+Current, but this mode also blits the depth buffer.
\item No\+Blit:\+ no blit. \doxylink{requirements_The}{The} GUI or external code will handle the blit.
