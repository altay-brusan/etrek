\doxysubsection{Detailed Description}
cut any dataset with a plane and generate a polygonal cut surface 

\doxylink{classvtk_plane_cutter}{vtk\+Plane\+Cutter} is a specialization of the \doxylink{classvtk_cutter}{vtk\+Cutter} algorithm to cut a dataset grid with a single plane. It is designed for performance and an exploratory, fast workflow. It produces output triangles/\+polygons that result from cutting the input dataset with the specified plane.

This algorithm is fast because it is threaded, it may delegate to a high-\/performance cutting algorithm, and/\+or it may build (in a preprocessing step) a spatial search structure that accelerates the plane cuts. \doxylink{requirements_The}{The} search structure, which is typically a sphere tree, is used to quickly cull candidate cells.

Because this filter may build an initial data structure during a preprocessing step, the first execution of the filter may take longer than subsequent operations. Typically the first execution is still faster than \doxylink{classvtk_cutter}{vtk\+Cutter} (especially with threading enabled), but for certain types of data this may not be true. However if you are using the filter to cut a dataset multiple times (as in an exploratory or interactive workflow) this filter typically works well.

\begin{DoxyWarning}{Warning}
Polygons can NOT be generated when the input is vtk\+Poly\+Data/\+vtk\+Unstructured\+Grid\+Base.

This filter chooses the output type based on the input type. 1) if input is \doxylink{classvtk_data_set}{vtk\+Data\+Set}, output is \doxylink{classvtk_poly_data}{vtk\+Poly\+Data}. 2) if input is \doxylink{classvtk_partitioned_data_set}{vtk\+Partitioned\+Data\+Set}, output is \doxylink{classvtk_partitioned_data_set}{vtk\+Partitioned\+Data\+Set}. 3) if input is \doxylink{classvtk_partitioned_data_set_collection}{vtk\+Partitioned\+Data\+Set\+Collection}, output is \doxylink{classvtk_partitioned_data_set_collection}{vtk\+Partitioned\+Data\+Set\+Collection}. 4) if input is \doxylink{classvtk_uniform_grid_a_m_r}{vtk\+Uniform\+Grid\+AMR}, output is \doxylink{classvtk_multi_block_data_set}{vtk\+Multi\+Block\+Data\+Set}. 5) if input is \doxylink{classvtk_multi_block_data_set}{vtk\+Multi\+Block\+Data\+Set}, output is \doxylink{classvtk_multi_block_data_set}{vtk\+Multi\+Block\+Data\+Set}.

Delegations to other filters:\+ 1) vtk\+Image\+Data/\+vtk\+Rectilinear\+Grid/\+vtk\+Structured\+Grid delegates \doxylink{classvtk_structured_data_plane_cutter}{vtk\+Structured\+Data\+Plane\+Cutter}. 2) \doxylink{classvtk_poly_data}{vtk\+Poly\+Data} with convex cells delegates to \doxylink{classvtk_poly_data_plane_cutter}{vtk\+Poly\+Data\+Plane\+Cutter}. 3) \doxylink{classvtk_unstructured_grid}{vtk\+Unstructured\+Grid} with linear cells delegates to \doxylink{classvtk3_d_linear_grid_plane_cutter}{vtk3\+DLinear\+Grid\+Plane\+Cutter}.

This filter can optionally produce output, using Merge\+Points=false, that has duplicate points. only for \doxylink{classvtk_unstructured_grid}{vtk\+Unstructured\+Grid}, and \doxylink{classvtk_poly_data}{vtk\+Poly\+Data} that all of its input cells are NOT convex polygons. For all the other input types, the output has unique points.

This class has been threaded with \doxylink{classvtk_s_m_p_tools}{vtk\+SMPTools}. Using TBB or other non-\/sequential type (set in the CMake variable VTK\+\_\+\+SMP\+\_\+\+IMPLEMENTATION\+\_\+\+TYPE) may improve performance significantly.
\end{DoxyWarning}
