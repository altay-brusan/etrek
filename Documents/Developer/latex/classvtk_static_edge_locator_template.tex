class vtk\+Static\+Edge\+Locator\+Template$<$ IDType, Edge\+Data $>$}
templated locator for managing edges and associated data on edges 

Templated on types of ids defining an edge, and any data associated with the edge.

\doxylink{classvtk_static_edge_locator_template}{vtk\+Static\+Edge\+Locator\+Template} provides methods for ordering and tracking edges, as well as associating data with edges. (An edge is a tuple (v0,v1) with v0 \texorpdfstring{$<$}{<} v1.) Typically this class may be used for isocontouring or any operation that operates on edges and needs to determine whether duplicates exist. \doxylink{requirements_The}{The} class is templated on 1) the type used to represent the id tuple; and 2) the data associated with the edge.

This class is non-\/incremental (i.\+e., static). That is, an array of edges must be provided and the locator is built from this array. Once the locator is built, incremental additions of new edges is not allowed (analogoues to \doxylink{classvtk_static_point_locator}{vtk\+Static\+Point\+Locator} and \doxylink{classvtk_static_cell_locator}{vtk\+Static\+Cell\+Locator}).

Finally, there are two distinct usage patterns for this class. One is to inject edges and then later search for them. This pattern begins with \doxylink{classvtk_static_edge_locator_template_ae3e9050eb5a859ab0a7e7879d15f904e}{Build\+Locator()} and then is followed by repeated calls to \doxylink{classvtk_static_edge_locator_template_a8ca4457daf9c423fa93ae3b164f30fc9}{Is\+Inserted\+Edge()}. Internally this operates on an array of \doxylink{classvtk_static_edge_locator_template_af2542e8e886e8c8359ef33bf5bc1a6bc}{Edge\+Tuple\+Type}. \doxylink{requirements_The}{The} second pattern also operates on an array of \doxylink{classvtk_static_edge_locator_template_af2542e8e886e8c8359ef33bf5bc1a6bc}{Edge\+Tuple\+Type}. It simply sorts an array of vtk\+Edge\+Tuple\+Type using \doxylink{classvtk_static_edge_locator_template_a71cfaec22ad5dc607e22ba3c42ff26f5}{Merge\+Edges()}, thereby grouping identical edges. An offset array is created that refers to the beginning of each group, hence indirectly indicating the number of unique edges, and providing O(1) access to each edge. Typically the offset array can be uses to renumber duplicate edges and/\+or data (such as points) associated with the edge.

\begin{DoxyWarning}{Warning}
\doxylink{requirements_The}{The} id tuple type can be specified via templating to reduce memory and speed processing.

Data is associated with edges (e.\+g., a parametric coordinate, or original id). By using the appropriate template parameter it is possible to associate other data with each edge. Note however that this data is not used when comparing and sorting the edges. (This could be changed -\/ define appropriate comparison operators.)

This class has been threaded with \doxylink{classvtk_s_m_p_tools}{vtk\+SMPTools}. Using TBB or other non-\/sequential type (set in the CMake variable VTK\+\_\+\+SMP\+\_\+\+IMPLEMENTATION\+\_\+\+TYPE) may improve performance significantly.
\end{DoxyWarning}

This method sorts (in place) an array of \doxylink{classvtk_static_edge_locator_template_af2542e8e886e8c8359ef33bf5bc1a6bc}{Edge\+Tuple\+Type} (of length num\+Edges) into separate groups, and allocates and returns an offset array providing access to each group. Each grouping is a list of duplicate edges. \doxylink{requirements_The}{The} method indicates the number of unique edges num\+Unique\+Edges. Note that the offset array end value offsets\+[num\+Unique\+Edges]\+ = num\+Edges, i.\+e., total allocation of the offsets array is num\+Unique\+Edges+1. Also note that the EId contained in the sorted Edge\+Tuples can be used to represent data on edges, and perform operations such as renumber edges from initial edge ids (possibly one of several duplicates) to unique edge ids.
