\doxysubsection{Detailed Description}
\doxylink{requirements_The}{The} class \doxylink{class_dcm_pixel_data}{Dcm\+Pixel\+Data} stores different pixel representations identified by a type (the transfer syntax) and some representation parameters \doxylink{requirements_The}{The} three unencapsulated transfer syntaxes belong to the same pixel representation. A type (or transfer syntax) conforms to a representation if the type and the representation type are equal or both are unencapsulated. If this is valid for the representation read or set by choose\+Representation then this representation is the conforming representation. else a representation with the default parameter set defined in the codec is the conforming representation.

For elements, the length includes the length of the tag, length field, VR field and the value itself, for items and sequences it returns the length of the complete item or sequence including delimitation tags if applicable. \begin{DoxyWarning}{Warning}
Since \doxylink{class_dcm_pixel_data_a71b688afdf1cb1a911da87ff017ec732}{calc\+Element\+Length()} returns a 32 bit integer, an overflow during calculation is possible for some derived classes that actually represent a compound value (e.\+g. items like \doxylink{class_dcm_pixel_item}{Dcm\+Pixel\+Item}). Such overflows will be detected, in which case the maximum possible value will be returned instead, coinciding with DCM\+\_\+\+Undefined\+Length. 

\doxylink{requirements_The}{The} implementation in \doxylink{class_dcm_pixel_data}{Dcm\+Pixel\+Data} may return zero if no conforming representation exists and set the EC\+\_\+\+Representation\+Not\+Found error flag to indicated it.

set or clear the flag that indicates that this pixel data element will be written in uncompressed (defined length) format even if the dataset itself is written in a compressed syntax where pixel data is normally written in encapsulated (undefined length) format. By default this flag is false, unless the dataset was read in an encapsulated transfer syntax and this pixel data element was already present in uncompressed format. This flag should never be enabled for pixel data elements on the main dataset level, only for pixel data elements within the icon image sequence or some other "{}private"{} place.
