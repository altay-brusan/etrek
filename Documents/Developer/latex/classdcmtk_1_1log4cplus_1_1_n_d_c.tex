\doxysubsection{Detailed Description}
\doxylink{requirements_The}{The} \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} class implements {\itshape nested diagnostic contexts} as defined by Neil Harrison in the article "{}\+Patterns for Logging \+Diagnostic Messages"{} part of the book "{}$<$i$>$\+Pattern Languages of \+Program Design 3$<$/\+i$>$"{} edited by Martin et al.

A Nested Diagnostic Context, or \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} in short, is an instrument to distinguish interleaved log output from different sources. Log output is typically interleaved when a server handles multiple clients near-\/simultaneously.

Interleaved log output can still be meaningful if each log entry from different contexts had a distinctive stamp. This is where NDCs come into play.

{\itshape {\bfseries{Note that NDCs are managed on a per thread basis}}}. \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} operations such as {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ad7b8f7c28f0c6e04265925b81271609a}{push}}, {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_a26bd6ea1c0368c986d2d73a91aed3b69}{pop}}, {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_a87a94fd58c4bb11b8c4d49085f5b1a96}{clear}}, {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_aacc8ca9186af6d8182eb15374459bf42}{get\+Depth}} and {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ab315a986116ab40c8b44040be1dc5f60}{set\+Max\+Depth}} affect the \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} of the {\itshape current} thread only. NDCs of other threads remain unaffected.

For example, a server can build a per client request \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} consisting the clients host name and other information contained in the the request. {\itshape Cookies} are another source of distinctive information. To build an \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} one uses the {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ad7b8f7c28f0c6e04265925b81271609a}{push}} operation. Simply put,


\begin{DoxyItemize}
\item Contexts can be nested.


\item When entering a context, call {\ttfamily \doxylink{ndc_8h_a4c227d9ac3d88f1803cafe54bae79cf4}{get\+NDC()}.\doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ad7b8f7c28f0c6e04265925b81271609a}{push()}}. As a side effect, if there is no nested diagnostic context for the current thread, this method will create it.


\item When leaving a context, call {\ttfamily \doxylink{ndc_8h_a4c227d9ac3d88f1803cafe54bae79cf4}{get\+NDC()}.\doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_a26bd6ea1c0368c986d2d73a91aed3b69}{pop()}}.


\item {\bfseries{When exiting a thread make sure to call {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ade8381173419fa118e2f8480315ea83b}{NDC.\+remove()}}}}. ~\newline
 
\end{DoxyItemize}

There is no penalty for forgetting to match each {\ttfamily push} operation with a corresponding {\ttfamily pop}, except the obvious mismatch between the real application context and the context set in the \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC}. Use of the {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_context_creator}{NDCContext\+Creator}} class can automate this process and make your code exception-\/safe.

If configured to do so, {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_pattern_layout}{log4cplus::\+\+Pattern\+Layout}} and {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_t_t_c_c_layout}{log4cplus::\+\+TTCCLayout}} instances automatically retrieve the nested diagnostic context for the current thread without any user intervention. Hence, even if a server is serving multiple clients simultaneously, the logs emanating from the same code (belonging to the same logger) can still be distinguished because each client request will have a different \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} tag.

Heavy duty systems should call the {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ade8381173419fa118e2f8480315ea83b}{remove}} method when leaving the run method of a thread. This ensures that the memory used by the thread can be freed.

A thread may inherit the nested diagnostic context of another (possibly parent) thread using the {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_aa1fc664ca0fefbf1e024a18db761b0f2}{inherit}} method. A thread may obtain a copy of its \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} with the {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ad33c2a5351fbb2cbc7b7652b4ceb49eb}{clone\+Stack}} method and pass the reference to any other thread, in particular to a child.

Remove the diagnostic context for this thread.

Each thread that created a diagnostic context by calling \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ad7b8f7c28f0c6e04265925b81271609a}{push()} should call this method before exiting. It is possible to omit this call if and only if each \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_ad7b8f7c28f0c6e04265925b81271609a}{push()} call is always paired with a \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_a26bd6ea1c0368c986d2d73a91aed3b69}{pop()} call (even in presence of thrown exceptions). Set maximum depth of this diagnostic context. If the current depth is smaller or equal to {\ttfamily max\+Depth}, then no action is taken.

This method is a convenient alternative to multiple {\ttfamily \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_a26bd6ea1c0368c986d2d73a91aed3b69}{pop}} calls. Moreover, it is often the case that at the end of complex call sequences, the depth of the \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c}{NDC} is unpredictable. \doxylink{requirements_The}{The} {\ttfamily set\+Max\+Depth} method circumvents this problem.

For example, the combination 
\begin{DoxyPre}
   void foo() \{
   ~  size\_t depth = \doxylink{classdcmtk_1_1log4cplus_1_1_n_d_c_aacc8ca9186af6d8182eb15374459bf42}{NDC.getDepth()};

   ~  ... complex sequence of calls

   ~  NDC.setMaxDepth(depth);
   \}
\end{DoxyPre}


ensures that between the entry and exit of foo the depth of the diagnostic stack is conserved.
