\doxysubsection{Detailed Description}
\subsubsection*{template$<$class DerivedT, class Value\+TypeT$>$\newline
class vtk\+Generic\+Data\+Array$<$ Derived\+T, Value\+Type\+T $>$}
Base interface for all typed \doxylink{classvtk_data_array}{vtk\+Data\+Array} subclasses. 

A more detailed description of this class and related tools can be found \href{https://docs.vtk.org/en/latest/design_documents/array_dispatch.html}{\texttt{here}}

\doxylink{requirements_The}{The} \doxylink{classvtk_generic_data_array}{vtk\+Generic\+Data\+Array} class provides a generic implementation of the \doxylink{classvtk_data_array}{vtk\+Data\+Array} API. It relies on subclasses providing access to data via 8 "{}concept methods"{}, which should be implemented as non-\/virtual methods of the subclass. These methods are:\+


\begin{DoxyItemize}
\item Value\+Type \doxylink{group__vtk_g_d_a_concept_methods_ga3b737766a3cf951e86fc05f037c332b5}{Get\+Value(vtk\+Id\+Type value\+Idx) const}
\item \+[public]\+ void \doxylink{group__vtk_g_d_a_concept_methods_ga2a10a84b0d936226d825455c5d3bf200}{Set\+Value(vtk\+Id\+Type value\+Idx, Value\+Type value)}
\item \+[public]\+ void \doxylink{group__vtk_g_d_a_concept_methods_ga71fe33d28f4d487761c05e16bb3f4412}{Get\+Typed\+Tuple(vtk\+Id\+Type tuple\+Idx, Value\+Type\texorpdfstring{$\ast$}{*} tuple) const}
\item \+[public]\+ void \doxylink{group__vtk_g_d_a_concept_methods_ga4e86b7b4d857dc8adf3197f26261375c}{Set\+Typed\+Tuple(vtk\+Id\+Type tuple\+Idx, const Value\+Type\texorpdfstring{$\ast$}{*} tuple)}
\item \+[public]\+ Value\+Type \doxylink{group__vtk_g_d_a_concept_methods_gab4f83e4e290869952fd69541edd01feb}{Get\+Typed\+Component(vtk\+Id\+Type tuple\+Idx, int comp\+Idx) const}
\item \+[public]\+ void Set\+Typed\+Component(vtk\+Id\+Type tuple\+Idx, int comp\+Idx,                                   Value\+Type value)
\item \+[protected]\+ bool \doxylink{group__vtk_g_d_a_concept_methods_gaedfda3b545f5da843f97b883da8e672c}{Allocate\+Tuples(vtk\+Id\+Type num\+Tuples)}
\item \+[protected]\+ bool \doxylink{group__vtk_g_d_a_concept_methods_gae5b79f6228cc4e2a928729e8b76b01b6}{Reallocate\+Tuples(vtk\+Id\+Type num\+Tuples)}
\end{DoxyItemize}

Note that these methods use the CRTP idiom, which provides static binding to avoid virtual calls. This allows the compiler to optimize away layers of indirection when these methods are used. Well-\/designed implementations of these methods will reduce to raw memory accesses, providing efficient performance comparable to working with the pointer data.

See \doxylink{classvtk_a_o_s_data_array_template}{vtk\+AOSData\+Array\+Template} and \doxylink{classvtk_s_o_a_data_array_template}{vtk\+SOAData\+Array\+Template} for example implementations.

In practice, code should not be written to use \doxylink{classvtk_generic_data_array}{vtk\+Generic\+Data\+Array} objects. Doing so is rather unweildy due to the CRTP pattern requiring the derived class be provided as a template argument. Instead, the \doxylink{classvtk_array_dispatch}{vtk\+Array\+Dispatch} framework can be used to detect a \doxylink{classvtk_data_array}{vtk\+Data\+Array}\textquotesingle{}s implementation type and instantiate appropriate templated worker code.

\doxylink{classvtk_array_dispatch}{vtk\+Array\+Dispatch} is also intended to replace code that currently relies on the encapsulation-\/breaking Get\+Void\+Pointer method. Not all subclasses of \doxylink{classvtk_data_array}{vtk\+Data\+Array} use the memory layout assumed by Get\+Void\+Pointer; calling this method on, e.\+g. a \doxylink{classvtk_s_o_a_data_array_template}{vtk\+SOAData\+Array\+Template} will trigger a deep copy of the array data into an AOS buffer. This is very inefficient and should be avoided.
