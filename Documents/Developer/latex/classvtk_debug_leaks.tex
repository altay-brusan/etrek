\doxysection{vtk\+Debug\+Leaks Class Reference}
\hypertarget{classvtk_debug_leaks}{}\label{classvtk_debug_leaks}\index{vtkDebugLeaks@{vtkDebugLeaks}}


identify memory leaks at program termination \doxylink{classvtk_debug_leaks}{vtk\+Debug\+Leaks} is used to report memory leaks at the exit of the program. It uses vtk\+Object\+Base::\+\+Initialize\+Object\+Base() (called via \doxylink{classvtk_object_factory}{vtk\+Object\+Factory} macros) to intercept the construction of all VTK objects. It uses the Un\+Register\+Internal method of \doxylink{classvtk_object_base}{vtk\+Object\+Base} to intercept the destruction of all objects.

\doxysubsection{Detailed Description}
identify memory leaks at program termination \doxylink{classvtk_debug_leaks}{vtk\+Debug\+Leaks} is used to report memory leaks at the exit of the program. It uses vtk\+Object\+Base::\+\+Initialize\+Object\+Base() (called via \doxylink{classvtk_object_factory}{vtk\+Object\+Factory} macros) to intercept the construction of all VTK objects. It uses the Un\+Register\+Internal method of \doxylink{classvtk_object_base}{vtk\+Object\+Base} to intercept the destruction of all objects. 

If not using the \doxylink{classvtk_object_factory}{vtk\+Object\+Factory} macros to implement \doxylink{classvtk_object_ab522226b135754e829b30804b4572427}{New()}, be sure to call vtk\+Object\+Base::\+\+Initialize\+Object\+Base() explicitly on the constructed instance. \doxylink{requirements_The}{The} rule of thumb is that wherever "{}new \+[some vtk\+Object\+Base subclass]\+"{} is called, vtk\+Object\+Base::\+\+Initialize\+Object\+Base() must be called as well.

There are exceptions to this:\+


\begin{DoxyItemize}
\item \doxylink{classvtk_command}{vtk\+Command} subclasses traditionally do not fully participate in \doxylink{classvtk_debug_leaks}{vtk\+Debug\+Leaks} registration, likely because they typically do not use vtk\+Type\+Macro to configure Get\+Class\+Name. Initialize\+Object\+Base should not be called on \doxylink{classvtk_command}{vtk\+Command} subclasses, and all such classes will be automatically registered with \doxylink{classvtk_debug_leaks}{vtk\+Debug\+Leaks} as "{}vtk\+Command or subclass"{}.
\item \doxylink{classvtk_information_key}{vtk\+Information\+Key} subclasses are not reference counted. They are allocated statically and registered automatically with a singleton "{}manager"{} instance. \doxylink{requirements_The}{The} manager ensures that all keys are cleaned up before exiting, and registration/\+deregistration with \doxylink{classvtk_debug_leaks}{vtk\+Debug\+Leaks} is bypassed.
\end{DoxyItemize}

A table of object name to number of instances is kept. At the exit of the program if there are still VTK objects around it will print them out. To enable this class add the flag -\/DVTK\+\_\+\+DEBUG\+\_\+\+LEAKS to the compile line, and rebuild \doxylink{classvtk_object}{vtk\+Object} and \doxylink{classvtk_object_factory}{vtk\+Object\+Factory}.

Ensure that {\itshape finalizer} is invoked before debug-\/leaks accounting is reported.

If your application holds VTK objects (i.\+e., instances of classes that inherit \doxylink{classvtk_object_base}{vtk\+Object\+Base}) for its duration, then adding {\itshape finalizer} function that frees them will prevent \doxylink{classvtk_debug_leaks}{vtk\+Debug\+Leaks} from reporting them as dangling references. This can occur if you declare static global variable that owns a reference to a VTK object (i.\+e., {\ttfamily static \doxylink{classvtk_new}{vtk\+New}\texorpdfstring{$<$}{<}X\texorpdfstring{$>$}{>} global;}). Because the order in which static variables are destroyed is not guaranteed, \doxylink{classvtk_debug_leaks}{vtk\+Debug\+Leaks} (which also depends on a static variable\textquotesingle{}s destruction to report leaks at the exit of the application) may be called before these other static globals are destroyed.

By adding a {\itshape finalizer}, you can release these references before leak reporting is performed. \Hypertarget{classvtk_debug_leaks_a6e33a4de9da0149a8a23b339dde3e7df}\index{vtkDebugLeaks@{vtkDebugLeaks}!ConstructClass@{ConstructClass}}
