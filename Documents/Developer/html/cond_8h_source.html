31/* NOTES ON THE CONVERSION OF THE DCMNET MODULE FROM CONDITION TO OFCONDITION
32 *
33 * All functions in this module have been adapted to the new OFCondition
34 * class which - unlike the CONDITION functions - does not create problems
35 * in multi-threaded code. The following notes explain the major differences
36 * and modifications needed in client code.
37 *
38 * - OFCondition is a class (CONDITION was just a typedef for long). This
39 * means that switch statements on conditions are not possible anymore.
40 * Use if/else if/else constructs instead.
41 *
42 * - The condition ASC_RELEASECONFIRMED has been removed.
43 * ASC_releaseAssociation() now returns EC_Normal upon successful completion.
44 *
45 * - No translation of error codes that are passed from the DUL module to the
46 * ASC or DIMSE module is performed anymore. That means that error codes
47 * such as DUL_PEERABORTEDASSOCIATION or DUL_PEERREQUESTEDRELEASE are now
48 * passed back to client code instead of their "aliases" with ASC_ or
49 * DIMSE_ prefix. Macros have been defined to catch most of these cases.
50 *
51 * - All normal status codes (DUL_NORMAL, DIMSE_NORMAL, ASC_NORMAL) have been
52 * mapped to EC_Normal. Macros have also been defined for these identifiers.
53 *
54 * - DUL_PEERREQUESTEDRELEASE is now an error code, i.e. unlike prior releases
55 * SUCCESS(DUL_PEERREQUESTEDRELEASE) is false.
56 */
