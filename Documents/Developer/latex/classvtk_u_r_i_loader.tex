\doxysubsection{Detailed Description}
Helper class for readers and importer that need to load more than one resource. 

\hypertarget{classvtk_u_r_i_loader_autotoc_md1023}{}\doxysubsubsection{\texorpdfstring{Introduction}{Introduction}}\label{classvtk_u_r_i_loader_autotoc_md1023}
{\ttfamily \doxylink{classvtk_u_r_i_loader}{vtk\+URILoader}} is a class that will load URIs, giving {\ttfamily \doxylink{classvtk_resource_stream}{vtk\+Resource\+Stream}}s from resolved resource. URI logic (parsing, resolution) is implemented in {\ttfamily \doxylink{classvtk_u_r_i}{vtk\+URI}}.

Some formats, such as GLTF, may refer to external resources through URIs. This URI loader can be used to solve this problem.

{\ttfamily \doxylink{classvtk_u_r_i_loader}{vtk\+URILoader}} provides "{}file"{} and "{}data"{} URIs loading. "{}file"{} URIs loading only supports localhost. More schemes may be supported in future versions.\hypertarget{classvtk_u_r_i_loader_autotoc_md1024}{}\doxysubsubsection{\texorpdfstring{Base URI}{Base URI}}\label{classvtk_u_r_i_loader_autotoc_md1024}
Base URI, specified in \href{https://datatracker.ietf.org/doc/html/rfc3986\#section-5}{\texttt{RFC3986\#5}}, is a concept that enable URIs to refer to relative resources from a base resource. For example, you can have a file that needs to look for another file next to it. \doxylink{requirements_The}{The} best way to implement this, is to have the first file as the base URI, and the referenced file as a relative reference.

To set a local file as base URI, you should use {\ttfamily \doxylink{classvtk_u_r_i_loader_a58e513ea2e08d67385463e4b0aabb848}{Set\+Base\+File\+Name}}, and for a local directory, you should use {\ttfamily \doxylink{classvtk_u_r_i_loader_aae609b281132f726069eaf1ce4efcd72}{Set\+Base\+Directory}}. These functions generate a "{}file"{} URI from given path. For example, calling {\ttfamily \doxylink{classvtk_u_r_i_loader_a58e513ea2e08d67385463e4b0aabb848}{Set\+Base\+File\+Name}("{}."{})} will generate the following URI:\+ {\ttfamily "{}\href{file:///}{\texttt{file:\+/\+/\+/\+}}\texorpdfstring{$<$}{<}absolute-\/current-\/working-\/directory\texorpdfstring{$>$}{>}/\+."{}}. These functions should be used because they handle some platform specific details, such as adding a {\ttfamily /\+} at the beginning of the path on Windows, percent-\/encoding, resolving relative paths, "{}."{} and "{}.."{}, checking that path exists and actual filesystem entry type is coherent.

If the loader has no base URI, it can only load full URIs. See {\ttfamily \doxylink{classvtk_u_r_i}{vtk\+URI}} for more information.\hypertarget{classvtk_u_r_i_loader_autotoc_md1025}{}\doxysubsubsection{\texorpdfstring{Basic usage}{Basic usage}}\label{classvtk_u_r_i_loader_autotoc_md1025}

When implementing a reader, you should use {\ttfamily \doxylink{classvtk_u_r_i_loader}{vtk\+URILoader}} if the format can contain URIs. Here are the global guidelines of URI loader support in a reader:\+
\begin{DoxyItemize}
\item \doxylink{requirements_The}{The} function should be named {\ttfamily Set\+URILoader}.
\item Depending on the format, the reader may require an URI loader, or just optionally use it.
\item \doxylink{requirements_The}{The} reader may use a default constructed URI loader by default. This would enable full URI loading, such as "{}data"{} URIs.
\item When reading from a file name, using {\ttfamily Set\+File\+Name} function, the reader should internally open a {\ttfamily \doxylink{classvtk_file_resource_stream}{vtk\+File\+Resource\+Stream}} on the file and create a {\ttfamily \doxylink{classvtk_u_r_i_loader}{vtk\+URILoader}} with a base URI set to {\ttfamily File\+Name}, then use the same code as the resource stream based reading. This prevents code duplication.
\end{DoxyItemize}\hypertarget{classvtk_u_r_i_loader_autotoc_md1027}{}\doxysubsubsection{\texorpdfstring{Extension}{Extension}}\label{classvtk_u_r_i_loader_autotoc_md1027}

It is a virtual function, so it can be reimplemented to let the user support additional schemes. In case you want do support additional scheme, URI scheme and host should be case-\/insensitive as specified in \href{https://datatracker.ietf.org/doc/html/rfc3986\#section-6.2.2.1}{\texttt{RFC3986\#6.\+2.\+2.\+1}}.
