\doxylink{requirements_The}{The} homography is internally represented and stored by a matrix which is available through the \doxylink{class_eigen_1_1_transform_a146347395d7dcfd250b6f9f96f9ed233}{matrix()} method. To understand the behavior of this class you have to think a \doxylink{class_eigen_1_1_transform}{Transform} object as its internal matrix representation. \doxylink{requirements_The}{The} chosen convention is right multiply:\+


\begin{DoxyCode}{0}

\end{DoxyCode}


Therefore, an affine transformation matrix M is shaped like this:\+

$ \left( \begin{array}{cc}
 linear & translation\\
 0 ... 0 & 1
 \end{array} \right) $

Note that for a projective transformation the last row can be anything, and then the interpretation of different parts might be slightly different.

However, unlike a plain matrix, the \doxylink{class_eigen_1_1_transform}{Transform} class provides many features simplifying both its assembly and usage. In particular, it can be composed with any other transformations (\doxylink{class_eigen_1_1_transform}{Transform},\doxylink{class_eigen_1_1_translation}{Translation},\doxylink{class_eigen_1_1_rotation_base}{Rotation\+Base},\doxylink{class_eigen_1_1_diagonal_matrix}{Diagonal\+Matrix}) and can be directly used to transform implicit homogeneous vectors. All these operations are handled via the operator\texorpdfstring{$\ast$}{*}. For the composition of transformations, its principle consists to first convert the right/\+left hand sides of the product to a compatible (Dim+1)\texorpdfstring{$^\wedge$}{\string^}2 matrix and then perform a pure matrix product. Of course, internally, operator\texorpdfstring{$\ast$}{*} tries to perform the minimal number of operations according to the nature of each terms. Likewise, when applying the transform to points, the latters are automatically promoted to homogeneous vectors before doing the matrix product. \doxylink{requirements_The}{The} conventions to homogeneous representations are performed as follow:\+

{\bfseries{\doxylink{class_eigen_1_1_translation}{Translation}}} t (Dim)x(1):\+    $ \left( \begin{array}{cc}
 I & t \\
 0\,...\,0 & 1
 \end{array} \right) $

{\bfseries{Rotation}} R (Dim)x(\+Dim):\+    $ \left( \begin{array}{cc}
 R & 0\\
 0\,...\,0 & 1
 \end{array} \right) $             {\bfseries{Scaling}} {\bfseries{\doxylink{class_eigen_1_1_diagonal_matrix}{Diagonal\+Matrix}}} S (Dim)x(\+Dim):\+    $ \left( \begin{array}{cc}
 S & 0\\
 0\,...\,0 & 1
 \end{array} \right) $

{\bfseries{Column}} {\bfseries{point}} v (Dim)x(1):\+    $ \left( \begin{array}{c}
 v\\
 1
 \end{array} \right) $

{\bfseries{Set}} {\bfseries{of}} {\bfseries{column}} {\bfseries{points}} V1...Vn (Dim)x(n):\+    $ \left( \begin{array}{ccc}
 v_1 & ... & v_n\\
 1 & ... & 1
 \end{array} \right) $

\doxylink{requirements_The}{The} concatenation of a \doxylink{class_eigen_1_1_transform}{Transform} object with any kind of other transformation always returns a \doxylink{class_eigen_1_1_transform}{Transform} object.

A little exception to the "{}as pure matrix product"{} rule is the case of the transformation of non homogeneous vectors by an affine transformation. In that case the last matrix row can be ignored, and the product returns non homogeneous vectors.

Since, for instance, a Dim x Dim matrix is interpreted as a linear transformation, it is not possible to directly transform Dim vectors stored in a Dim x Dim matrix. \doxylink{requirements_The}{The} solution is either to use a Dim x Dynamic matrix or explicitly request a vector transformation by making the vector homogeneous:\+ 
\begin{DoxyCode}{0}

\end{DoxyCode}
 Note that there is zero overhead.

Conversion methods from/\+to Qt\textquotesingle{}s QMatrix and QTransform are available if the preprocessor token EIGEN\+\_\+\+QT\+\_\+\+SUPPORT is defined.
