\doxysubsection{Detailed Description}
superclass for callback/\+observer methods 

\doxylink{classvtk_command}{vtk\+Command} is an implementation of the observer/\+command design pattern. In this design pattern, any instance of \doxylink{classvtk_object}{vtk\+Object} can be "{}observed"{} for any events it might invoke. For example, \doxylink{classvtk_renderer}{vtk\+Renderer} invokes a Start\+Event as it begins to render and a End\+Event when it finishes rendering. Filters (subclasses of vtk\+Process\+Object) invoke Start\+Event, Progress\+Event, and End\+Event as the filter processes data. Observers of events are added with the Add\+Observer() method found in \doxylink{classvtk_object}{vtk\+Object}. Add\+Observer(), besides requiring an event id or name, also takes an instance of \doxylink{classvtk_command}{vtk\+Command} (or a subclasses). Note that \doxylink{classvtk_command}{vtk\+Command} is meant to be subclassed, so that you can package the information necessary to support your callback.

Event processing can be organized in priority lists, so it is possible to truncate the processing of a particular event by setting the Abort\+Flag variable. \doxylink{requirements_The}{The} priority is set using the Add\+Observer() method. By default the priority is 0, events of the same priority are processed in last-\/in-\/first-\/processed order. \doxylink{requirements_The}{The} ordering/\+aborting of events is important for things like 3D widgets, which handle an event if the widget is selected (and then aborting further processing of that event). Otherwise. the event is passed along for further processing.

When an instance of \doxylink{classvtk_object}{vtk\+Object} invokes an event, it also passes an optional void pointer to a call\+Data. This call\+Data is nullptr most of the time. \doxylink{requirements_The}{The} call\+Data is not specific to a type of event but specific to a type of \doxylink{classvtk_object}{vtk\+Object} invoking a specific event. For instance, vtk\+Command::\+\+Pick\+Event is invoked by \doxylink{classvtk_prop}{vtk\+Prop} with a nullptr call\+Data but is invoked by \doxylink{classvtk_interactor_style_image}{vtk\+Interactor\+Style\+Image} with a pointer to the \doxylink{classvtk_interactor_style_image}{vtk\+Interactor\+Style\+Image} object itself.
