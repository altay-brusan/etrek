\doxysubsection{Detailed Description}
represent and manipulate fields of data 

\doxylink{classvtk_field_data}{vtk\+Field\+Data} represents and manipulates fields of data. \doxylink{requirements_The}{The} model of a field is a m x n matrix of data values, where m is the number of tuples, and n is the number of components. (A tuple is a row of n components in the matrix.) \doxylink{requirements_The}{The} field is assumed to be composed of a set of one or more data arrays, where the data in the arrays are of different types (e.\+g., int, double, char, etc.), and there may be variable numbers of components in each array. Note that each data array is assumed to be "{}m"{} in length (i.\+e., number of tuples), which typically corresponds to the number of points or cells in a dataset. Also, each data array must have a character-\/string name. (This is used to manipulate data.)

There are two ways of manipulating and interfacing to fields. You can do it generically by manipulating components/\+tuples via a double-\/type data exchange, or you can do it by grabbing the arrays and manipulating them directly. \doxylink{requirements_The}{The} former is simpler but performs type conversion, which is bad if your data has non-\/castable types like (void) pointers, or you lose information as a result of the cast. \doxylink{requirements_The}{The} more efficient method means managing each array in the field. Using this method you can create faster, more efficient algorithms that do not lose information.

{\ttfamily \doxylink{classvtk_field_data_a7255a069538e8bf878737dfa7ef93a54}{Ranges}} and {\ttfamily Finite\+Ranges} store cached ranges for arrays stored in this field data. Given the array at index {\ttfamily idx}, 2 ranges are stored:\+ the magnitude range at {\ttfamily \doxylink{classvtk_field_data_a7255a069538e8bf878737dfa7ef93a54}{Ranges}\+[idx]\+\+[0]\+}, and all the component ranges at {\ttfamily \doxylink{classvtk_field_data_a7255a069538e8bf878737dfa7ef93a54}{Ranges}\+[idx]\+\+[1]\+}. \doxylink{requirements_The}{The} ranges are stored in the third component of the tuple {\ttfamily Cached\+Ghost\+Range\+Type}. For the component ranges, they are stored in an array of size 2 times the number of components, storing {\ttfamily \+[min0, max0, ..., minn, maxn]\+}.
