\item[{\parbox[t]{\linewidth}{Class \doxylink{classvtk_socket_controller}{vtk\+Socket\+Controller} }}]\hfill \\
\label{bug__bug000006}%
\Hypertarget{bug__bug000006}%
 Note that because process 0 will always correspond to self, this class breaks assumptions usually implied when using ad-\/hoc polymorphism. That is, the \doxylink{classvtk_socket_controller}{vtk\+Socket\+Controller} will behave differently than other subclasses of \doxylink{classvtk_multi_process_controller}{vtk\+Multi\+Process\+Controller}. If you upcast \doxylink{classvtk_socket_controller}{vtk\+Socket\+Controller} to \doxylink{classvtk_multi_process_controller}{vtk\+Multi\+Process\+Controller} and send it to a method that does not know that the object is actually a \doxylink{classvtk_socket_controller}{vtk\+Socket\+Controller}, the object may not behave as intended. For example, if that oblivious class chose to identify a "{}root"{} based on the local process id, then both sides of the controller will think they are the root (and that will probably lead to deadlock). If you plan to upcast to \doxylink{classvtk_multi_process_controller}{vtk\+Multi\+Process\+Controller}, you should probably use the Create\+Compliant\+Controller instead.
