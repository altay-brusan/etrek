\doxysubsection{Detailed Description}
platform-\/independent render window interaction including picking and frame rate control. 

\doxylink{classvtk_render_window_interactor}{vtk\+Render\+Window\+Interactor} provides a platform-\/independent interaction mechanism for mouse/\+key/\+time events. It serves as a base class for platform-\/dependent implementations that handle routing of mouse/\+key/\+timer messages to \doxylink{classvtk_interactor_observer}{vtk\+Interactor\+Observer} and its subclasses. \doxylink{classvtk_render_window_interactor}{vtk\+Render\+Window\+Interactor} also provides controls for picking, rendering frame rate, and headlights.

\doxylink{classvtk_render_window_interactor}{vtk\+Render\+Window\+Interactor} has changed from previous implementations and now serves only as a shell to hold user preferences and route messages to \doxylink{classvtk_interactor_style}{vtk\+Interactor\+Style}. Callbacks are available for many events. Platform specific subclasses should provide methods for manipulating timers, Terminate\+App, and an event loop if required via Initialize/\+\+Start/\+\+Enable/\+\+Disable.

\begin{DoxyWarning}{Warning}
\doxylink{classvtk_render_window_interactor}{vtk\+Render\+Window\+Interactor} routes events through VTK\textquotesingle{}s command/\+observer design pattern. That is, when \doxylink{classvtk_render_window_interactor}{vtk\+Render\+Window\+Interactor} (actually, one of its subclasses) sees a platform-\/dependent event, it translates this into a VTK event using the \doxylink{classvtk_object_a8c10fc51d6ce89760e02d4d81f4f54c3}{Invoke\+Event()} method. Then any vtk\+Interactor\+Observers registered for that event are expected to respond as appropriate.
\end{DoxyWarning}

This flag is useful when you are integrating VTK in a larger system. In such cases, an application can lock up if the {\ttfamily \doxylink{classvtk_render_window_interactor_a70e8c7193c6dfca441860f7826ba8007}{Start()}} method in \doxylink{classvtk_render_window_interactor}{vtk\+Render\+Window\+Interactor} processes events indefinitely without giving the system a chance to execute anything. \doxylink{requirements_The}{The} default value for this flag is true. It currently only affects VTK webassembly applications.

As an example with webassembly in the browser through emscripten SDK:\+
\begin{DoxyEnumerate}
\item If your app has an {\ttfamily int main} entry point, leave this value enabled. Emscripten will simulate an infinite event loop and avoid running code after {\ttfamily interactor-\/\texorpdfstring{$>$}{>}\doxylink{classvtk_render_window_interactor_a70e8c7193c6dfca441860f7826ba8007}{Start()}} which is usually the end of {\ttfamily main}. Otherwise, all VTK objects will go out of scope immediately without giving a chance for user interaction with the render window.
\item If your app does not have an {\ttfamily int main} entry point, disable this behavior. Otherwise, the webassembly application will not start up successfully.
