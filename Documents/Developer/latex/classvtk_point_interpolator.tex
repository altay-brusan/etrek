\doxysubsection{Detailed Description}
interpolate over point cloud using various kernels 

\doxylink{classvtk_point_interpolator}{vtk\+Point\+Interpolator} probes a point cloud Pc (the filter Source) with a set of points P (the filter Input), interpolating the data values from Pc onto P. Note however that the descriptive phrase "{}point cloud"{} is a misnomer:\+ Pc can be represented by any \doxylink{classvtk_data_set}{vtk\+Data\+Set} type, with the points of the dataset forming Pc. Similarly, the output P can also be represented by any \doxylink{classvtk_data_set}{vtk\+Data\+Set} type; and the topology/\+geometry structure of P is passed through to the output along with the newly interpolated arrays.

A key input to this filter is the specification of the interpolation kernel, and the parameters which control the associated interpolation process. Interpolation kernels include Voronoi, Gaussian, Shepard, and SPH (smoothed particle hydrodynamics), with additional kernels to be added in the future.

An overview of the algorithm is as follows. For each p from P, Np "{}close"{} points to p are found. (\doxylink{requirements_The}{The} meaning of what is "{}close"{} can be specified as either the N closest points, or all points within a given radius Rp. This depends on how the kernel is defined.) Once the Np close points are found, then the interpolation kernel is applied to compute new data values located on p. Note that for reasonable performance, finding the Np closest points requires a point locator. \doxylink{requirements_The}{The} locator may be specified as input to the algorithm. (By default, a \doxylink{classvtk_static_point_locator}{vtk\+Static\+Point\+Locator} is used because generally it is much faster to build, delete, and search with. However, with highly non-\/uniform point distributions, octree-\/ or kd-\/tree based locators may perform better.)

\begin{DoxyWarning}{Warning}
This class has been threaded with \doxylink{classvtk_s_m_p_tools}{vtk\+SMPTools}. Using TBB or other non-\/sequential type (set in the CMake variable VTK\+\_\+\+SMP\+\_\+\+IMPLEMENTATION\+\_\+\+TYPE) may improve performance significantly.

For widely spaced points in Pc, or when p is located outside the bounding region of Pc, the interpolation may behave badly and the interpolation process will adapt as necessary to produce output. For example, if the N closest points within R are requested to interpolate p, if N=0 then the interpolation will switch to a different strategy (which can be controlled as in the Null\+Points\+Strategy).
\end{DoxyWarning}
