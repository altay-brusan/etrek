31/*
32 * Short description of configuration file structure:
33 * - The data in a configuration file have a tree structure.
34 * The tree has a depth defined at instantiation time (by default, OFConfigFile_MaxLevel),
35 * not including the (imaginary) root node.
36 * - A level 0 entry (a leaf) has the form: KEYWORD = VALUE,
37 * where the keyword starts on row one of a line.
38 * - A level 1 entry has the form [KEYWORD]
39 * - A level 2 entry has the form [[KEYWORD]] (and so on).
40 * - Keywords may consist of:
41 * A..Z, a..z (which are converted to uppercase),
42 * 0..9,
43 * '-'
44 * - Values can be any kind of ASCII text. Values may span multiple lines.
45 * To continue a value in the next line, the next line MUST start with
46 * (any amount of) whitespace, which is discarded when reading the value.
47 * linefeeds (converted to ASCII 10 if necessary) are kept in the
48 * value string. Empty lines are discarded (and also their linefeed).
49 * - The data must have a "clean" tree structure. This means that there
50 * MUST be a level 2 keyword before any level 1 keyword etc.
51 * - lines starting with the comment char (default is "#") are interpreted
52 * as comment lines.
53 *
54 */
55
56#define OFConfigFile_MaxLevel 2
57#define OFConfigFile_CommentChar '#'
