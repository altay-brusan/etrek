39 * LZ4F also offers streaming capabilities.

41 * lz4.h is not required when using lz4frame.h,
42 * except to extract common constants such as LZ4_VERSION_NUMBER.

522/* A Dictionary is useful for the compression of small messages (KB range).
523 * It dramatically improves compression efficiency.
524 *
525 * LZ4 can ingest any input as dictionary, though only the last 64 KB are useful.
526 * Better results are generally achieved by using Zstandard's Dictionary Builder
527 * to generate a high-quality dictionary from a set of samples.
528 *
529 * The same dictionary will have to be used on the decompression side
530 * for decoding to be successful.
531 * To help identify the correct dictionary at decoding stage,
532 * the frame header allows optional embedding of a dictID field.
533 */
534

569/* Loading a dictionary has a cost, since it involves construction of tables.
570 * The Bulk processing dictionary API makes it possible to share this cost
571 * over an arbitrary number of compression jobs, even concurrently,
572 * markedly improving compression latency for these cases.
573 *
574 * Note that there is no corresponding bulk API for the decompression side,
575 * because dictionary does not carry any initialization cost for decompression.
576 * Use the regular LZ4F_decompress_usingDict() there.
577 */
