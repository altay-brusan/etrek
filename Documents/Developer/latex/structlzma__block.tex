\doxysubsection{Detailed Description}
Options for the Block and Block Header encoders and decoders. 

Different Block handling functions use different parts of this structure. Some read some members, other functions write, and some do both. Only the members listed for reading need to be initialized when the specified functions are called. \doxylink{requirements_The}{The} members marked for writing will be assigned new values at some point either by calling the given function or by later calls to lzma\+\_\+code().

\doxymbox{\hyperlink{vli_8h_a1dbc0ffc3e72748f64df8f7f71898272}{lzma\+\_\+vli}} lzma\+\_\+block::\+compressed\+\_\+size}



Size of the Compressed Data in bytes. 

Encoding:\+ If this is not LZMA\+\_\+\+VLI\+\_\+\+UNKNOWN, Block Header encoder will store this value to the Block Header. Block encoder doesn\textquotesingle{}t care about this value, but will set it once the encoding has been finished.

Decoding:\+ If this is not LZMA\+\_\+\+VLI\+\_\+\+UNKNOWN, Block decoder will verify that the size of the Compressed Data field matches compressed\+\_\+size.

Usually you don\textquotesingle{}t know this value when encoding in streamed mode, and thus cannot write this field into the Block Header.

In non-\/streamed mode you can reserve space for this field before encoding the actual Block. After encoding the data, finish the Block by encoding the Block Header. Steps in detail:\+


\begin{DoxyItemize}
\item Set compressed\+\_\+size to some big enough value. If you don\textquotesingle{}t know better, use LZMA\+\_\+\+VLI\+\_\+\+MAX, but remember that bigger values take more space in Block Header.
\item Call lzma\+\_\+block\+\_\+header\+\_\+size() to see how much space you need to reserve for the Block Header.
\item Encode the Block using lzma\+\_\+block\+\_\+encoder() and lzma\+\_\+code(). It sets compressed\+\_\+size to the correct value.
\item Use lzma\+\_\+block\+\_\+header\+\_\+encode() to encode the Block Header. Because space was reserved in the first step, you don\textquotesingle{}t need to call lzma\+\_\+block\+\_\+header\+\_\+size() anymore, because due to reserving, header\+\_\+size has to be big enough. If it is "{}too big"{}, lzma\+\_\+block\+\_\+header\+\_\+encode() will add enough Header Padding to make Block Header to match the size specified by header\+\_\+size.
\end{DoxyItemize}
