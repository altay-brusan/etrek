LZMA1 Filter ID (for raw encoder/\+decoder only, not in .xz). 

LZMA1 is the very same thing as what was called just LZMA in LZMA Utils, 7-\/Zip, and LZMA SDK. It\textquotesingle{}s called LZMA1 here to prevent developers from accidentally using LZMA when they actually want LZMA2. \Hypertarget{lzma12_8h_a98a7fd42aa78a273a6b138629e46772d}\index{lzma12.h@{lzma12.h}!LZMA\_FILTER\_LZMA1EXT@{LZMA\_FILTER\_LZMA1EXT}}

\+\#define LZMA\+\_\+\+FILTER\+\_\+\+LZMA1\+EXT~\doxymbox{\hyperlink{vli_8h_a2d8bf5322898bfa11945848420585881}{LZMA\+\_\+\+VLI\+\_\+C}}(0x4000000000000002)}



LZMA1 Filter ID with extended options (for raw encoder/\+decoder). 

This is like LZMA\+\_\+\+FILTER\+\_\+\+LZMA1 but with this ID a few extra options are supported in the \doxylink{structlzma__options__lzma}{lzma\+\_\+options\+\_\+lzma} structure:\+


\begin{DoxyItemize}
\item A flag to tell the encoder if the end of payload marker (EOPM) alias end of stream (EOS) marker must be written at the end of the stream. In contrast, LZMA\+\_\+\+FILTER\+\_\+\+LZMA1 always writes the end marker.
\item Decoder needs to be told the uncompressed size of the stream or that it is unknown (using the special value UINT64\+\_\+\+MAX). If the size is known, a flag can be set to allow the presence of the end marker anyway. In contrast, LZMA\+\_\+\+FILTER\+\_\+\+LZMA1 always behaves as if the uncompressed size was unknown.
\end{DoxyItemize}

This allows handling file formats where LZMA1 streams are used but where the end marker isn\textquotesingle{}t allowed or where it might not (always) be present. This extended LZMA1 functionality is provided as a Filter ID for raw encoder and decoder instead of adding new encoder and decoder initialization functions because this way it is possible to also use extra filters, for example, LZMA\+\_\+\+FILTER\+\_\+\+X86 in a filter chain with LZMA\+\_\+\+FILTER\+\_\+\+LZMA1\+EXT, which might be needed to handle some file formats. \Hypertarget{lzma12_8h_a04f9d9a018a47cc99491e6e94e92f96b}\index{lzma12.h@{lzma12.h}!LZMA\_FILTER\_LZMA2@{LZMA\_FILTER\_LZMA2}}

If you will use LZMA\+\_\+\+SYNC\+\_\+\+FLUSH often, the hash chains may be a better choice, because binary trees get much higher compression ratio penalty with LZMA\+\_\+\+SYNC\+\_\+\+FLUSH.

0 is the fastest and 9 is the slowest. These match the switches -\/0 .. -\/9 of the xz command line tool. In addition, it is possible to bitwise-\/or flags to the preset. Currently only LZMA\+\_\+\+PRESET\+\_\+\+EXTREME is supported. \doxylink{requirements_The}{The} flags are defined in \doxylink{container_8h}{container.\+h}, because the flags are used also with lzma\+\_\+easy\+\_\+encoder().

\doxylink{requirements_The}{The} preset levels are subject to changes between liblzma versions.

This function is available only if LZMA1 or LZMA2 encoder has been enabled when building liblzma.

If features (like certain match finders) have been disabled at build time, then the function may return success (false) even though the resulting LZMA1/\+\+LZMA2 options may not be usable for encoder initialization (LZMA\+\_\+\+OPTIONS\+\_\+\+ERROR).
