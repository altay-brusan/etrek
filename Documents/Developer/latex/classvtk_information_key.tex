\doxysubsection{Detailed Description}
Superclass for \doxylink{classvtk_information}{vtk\+Information} keys. 

\doxylink{classvtk_information_key}{vtk\+Information\+Key} is the superclass for all keys used to access the map represented by \doxylink{classvtk_information}{vtk\+Information}. \doxylink{requirements_The}{The} \doxylink{classvtk_information_ab200fc63d85a6cfc013edc6ef89102c7}{vtk\+Information::\+\+Set} and vtk\+Information::\+\+Get methods of \doxylink{classvtk_information}{vtk\+Information} are accessed by information keys. A key is a pointer to an instance of a subclass of \doxylink{classvtk_information_key}{vtk\+Information\+Key}. \doxylink{requirements_The}{The} type of the subclass determines the overload of Set/\+\+Get that is selected. This ensures that the type of value stored in a \doxylink{classvtk_information}{vtk\+Information} instance corresponding to a given key matches the type expected for that key.

This function is only relevant when the pertaining key is used in a VTK pipeline. Specific keys that handle pipeline data requests (for example, UPDATE\+\_\+\+PIECE\+\_\+\+NUMBER) can overwrite this method to store in the data information meta-\/data about the request that led to the current filter execution. This meta-\/data can later be used to compare what is being requested to decide whether the filter needs to re-\/execute. For example, a filter may store the current UPDATE\+\_\+\+PIECE\+\_\+\+NUMBER in the data object\textquotesingle{}s information as the DATA\+\_\+\+PIECE\+\_\+\+NUMBER. DATA\+\_\+\+PIECE\+\_\+\+NUMBER can later be compared to a new UPDATA\+\_\+\+PIECE\+\_\+\+NUMBER to decide whether a filter should re-\/execute.
